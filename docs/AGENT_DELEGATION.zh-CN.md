# Capri 多 Agent 与复杂任务分工

2026-11-02：第九项六个子项的首版实现。新增受预算和文件能力限制的子任务控制器，复用当前模型传输、文件工具、项目规则、代码快照和任务恢复语义。本轮只做电脑侧验证，没有连接、安装或操作手机。

## 9.1 子任务上下文隔离

`agent/delegation/DelegateEngine` 为每个子任务建立独立消息数组、文件快照、工具登记和执行证据。不会复制整段父对话、人格、个人记忆、Skill 正文、账号或附件，也不把子 Agent 注册为新的用户聊天。

交接包包含：一个最多 2,000 字符的目标、最多 12 条各 400 字符的补充约束、父任务当前完整用户要求账本、声明文件和最多 4 个真实父工具结果引用。父要求超过 8,000 字符或实际子上下文超限时拒绝继续，不静默丢弃用户纠正；此时主任务直接处理或重新缩小分工。父引用只接受文件、网页与执行证据，拒绝通过引用继承个人记忆、账号／手机、Skill 或 MCP 工具结果。父结果每条最多提供 2,000 字符，标注原结果摘要和截断；截断片段不能冒充完整的正向完成证据。

父任务已加载的 Skill 如对子任务必要，由主任务提炼相关约束或准备必要文件；子任务不自行继承 Skill 发现／加载权限。引用、文件和摘录都是数据，不能扩大授权。子模型使用父任务已冻结的模型与服务配置，不增加模型路由或凭证披露目的地。

## 9.2 按职责限制能力

角色为 `investigator / reviewer / coder`，默认只获得 `list_files / read_file / search_files / project`。只有显式 `allow_write=true` 的 coder 能使用 `write_file / edit_file`，且目标必须精确匹配 `write_paths`。

所有子任务都没有手机、浏览器、联网检索、Shell、Python、程序内核、MCP、环境安装、记忆写入、发文件或继续委派的入口。调查限于声明的本地来源；主任务可先检索外部资料，再传实际结果引用。这样避免复制登录态和账号能力，也避免检索工具的额外费用绕过模型预算。

子工具批次先整体校验名称、参数、唯一调用 ID、数量和写入归属，再执行第一项。一个批次中混入越权工具时，前面的合法写入也不会先执行。`delegate_finish` 必须单独调用；模型的纯文本“做完了”不会作为完成回执。

这是应用工具路由层的隔离，不是新的 Android UID 或允许任意代码运行的强沙箱。子任务只有受控文件 API，不启动进程。

## 9.3 父子预算和资源统筹

| 范围 | 限制 |
| --- | --- |
| 单组委派 | 1–3 个子任务；120 秒截止时间，含子任务资源排队与模型等待 |
| 全应用子任务 | 最多 2 个同时运行 |
| 全应用模型请求 | 父执行、压缩、人物表达和子推理共同经过 3 个推理许可 |
| 单个子任务 | 最多 4 轮推理、16 次普通工具调用；工具批次最多 8 项／128,000 字符 |
| 子上下文／输出 | 输入估算上限不超过父输入预算及 8,192 token；单次输出不超过父输出限制及 2,048 token |
| 同一父执行轮 | 全部子任务及所有分组共用 8 次推理尝试、48,000 token credit，网络重试也占用 |
| 父任务全局请求 | 子调用消耗原有父请求额度，不额外发放独立请求池；为父核验／收尾保留至少 2 次执行和既有人物表达额度 |

`ModelRequests` 对额度检查、尝试编号和计数采用同步预留，避免两个子请求同时越过末次额度。每次传输重试都重新检查共享 credit；失败尝试的估算不退款。收到更大的实际 usage 时补记差额，阻止后续继续超额；未返回 usage 明确记录为未知。估算 credit 不等于实际账单，也不能阻止已经在途的响应造成估算偏差；没有伪造人民币／美元上限。

父子总模型并发在 `ModelTransport` 限制，新增 `model_admission` 排队测量，和现有 HTTP dispatcher 排队区分。`Purpose.DELEGATION` 单独统计请求、usage 和耗时；`agent_timing.py` 对并行区间取并集，不把两个并行子模型时间再叠加到父工具耗时。

额度边界与现有主循环一致，按一次父执行轮计算；显式继续会开启新轮额度，不是跨应用重启的永久金额账户。幂等回执仍防止同一旧操作自动重跑。长期目标预算属于第十项。

## 9.4 独立文件提案与受保护合并

每个子任务只复制精确声明的 UTF-8 文件和写入目标，不克隆整个仓库、Git 元数据、HOME 或依赖目录。自动加入目标的祖先 `AGENTS.md`，包括不存在规则文件的基线，避免后来新增规则被忽略。最多 32 个声明文件，连规则路径最多 64 项；单个输入最多 512 KiB，每个子快照总输入最多 2 MB。拒绝路径越界、符号链接、二进制和私有／依赖目录。

快照位于 `agent-delegates/<chat>/<history-scope>/<group>/<child>/`，与父工作区和兄弟任务分开。兄弟写入路径必须互不重叠；子任务不能删除文件或改写 AGENTS.md。输入复制使用父文件工具共享的读锁，子写入只作用于各自快照。提案逐文件保存前后内容摘要，单个变更文件最多 1 MB、合计最多 2 MB。

`merge(group_id, task_id, expected_proposal)` 才会修改父文件，必须满足：

1. 子任务为完整 `proposal_ready`，有实际变更，提案摘要与调用者检查的版本相同。
2. 当前父用户要求与创建提案时相同，且没有待接入的新输入。
3. 全部输入和规则基线仍匹配，包括原先不存在的规则／目标没有被新增。
4. 私有提案文件仍匹配已发布的内容摘要。

合并复用普通文件工具的写锁、项目规则、版本检查、取消回调和 Coding 快照。新增文件使用 `expected_absent`，已有文件使用 `expected_sha256`。未读项目规则会先返回规则而不写入，主任务审阅后才能再次提交；恢复旧提案不会绕过规则。

已应用文件若引入语法诊断错误，合并与后续汇总保留 `partial / result_incomplete`；重复合并只返回原回执，不重放写入。

文件合并不是跨文件事务，也不强制锁住外部终端写入。逐项持久保存意图与实际结果；中途停止、后续失败或进程死亡可能留下部分父文件修改，不自动回滚用户后续内容。未知合并标记 `merge_interrupted / parent_effect=unknown`，禁止自动重试，必须读取当前文件与已有快照核对。单文件仍沿用现有文件工具的原子替换及版本检查语义。

同一提案的成功合并再次调用只返回原回执。新目标或用户纠正后的旧提案不能直接合并；主任务可重新分工，或读取提案后按当前要求通过普通文件工具审查应用。独立分工应避免把一个兄弟将修改的文件当成另一个兄弟的稳定输入，否则后合并者会得到版本冲突。

## 9.5 结构化结果、恢复与取消

主工具 `agent_delegate` 提供：

- `run`：等待这一组结束，返回子任务 ID、状态、简短结论、产物数量、提案摘要、共享预算和耗时。
- `list(offset)`：当前聊天／历史范围的委派元数据，每页最多 4 组；用于恢复 ID。
- `read`：读取某个子结果、工具证据或已发布产物，文本最多 8,000 字符一页，返回续读偏移；产物重新核对摘要。
- `merge`：受保护地应用指定 coder 的预期提案。
- `discard`：丢弃私有快照。不会回滚已修改的父文件。

子回执区分 `completed / proposal_ready / partial / blocked / budget / interrupted / stale_inputs / failed`，合并另有部分或未知状态。完成必须引用已交付的真实正向子工具结果或完整父证据，并声明没有未决项；部分／阻塞结果可引用真实失败。源码／规则在执行期间变化时，结果标记过期，不能装成当前成功结果。过大的工具结果保留在独立证据记录中，子上下文只收到截断提示，要求缩小读取或报告部分结果，不伪装已看完。

`has_unmerged_proposals=true` 不能作为父完成证据。只读调查回执可支持父核验，但仍是子模型的有来源判断，不独立证明用户目标。合并成功也只说明文件应用，`verification_required=true` 提醒父任务继续相关构建／检查和最终交付。

同一父任务 origin、历史范围和 `request_key` 绑定一个委派 ID；相同输入返回回执，输入不同拒绝复用旧 key。应用重启不重发模型请求或重新执行工具。源文件、项目规则和提案摘要都留在范围内，不从 PID 或另一个聊天认领任务。

停止父任务向子协程和现有可取消 HTTPS 传输传播。收到新要求时中断子任务，父循环先接入纠正，不派发旧模型响应；合并在文件边界检查同一事件代次。已开始的单文件操作和模型服务端计算不承诺撤销或退款。

每聊天最多 32 份未退役记录，私有存储在下一组开始前检查 64 MiB 阈值，单组制作快照和运行日志可产生有限增量。不自动删除未审阅提案或未知合并。可回收旧输出时保留小型幂等指针，避免“删了日志就当没做过”；最多 512 个指针，达到容量后使用直接工具或新的任务聊天。只识别控制器固定布局的 record.json，项目中同名文件仍是数据。聊天删除与共同经历重置同步清理这些记录和未合并提案；父工作区保留原有语义。

## 9.6 何时委派与离线对照

工具契约和主执行提示明确要求选择性委派，原因是独立调查、独立审查或互不重叠的编码。单次查询、小修改、依赖前一步结果的操作、手机／登录态／执行环境工作优先由父任务直接完成。当前没有自动“每轮启动多个 Agent”的策略。

可选 `parallel=false` 使用相同隔离和预算串行执行，便于比较。电脑上的确定性文件审查夹具，给每次模拟模型响应加入相同的 30 ms 延迟，得到一次样本：

| 方式 | 主机耗时 | 模拟模型请求 | 两个来源核对 |
| --- | ---: | ---: | --- |
| 单 Agent，批量直接读取 | 73 ms | 2 | 通过 |
| 串行子任务 | 165 ms | 4 | 通过 |
| 并行子任务 | 93 ms | 4 | 通过 |

这个小任务中，并行减少了相对子任务串行的等待，却没有超过单 Agent 的请求效率。样本只验证控制器、证据与并发边界，不是真实模型成功率，也没有测量 DeepSeek 费用、缓存、手机耗电或复杂项目收益。真实任务需固定模型和环境再比较，不能据此宣称多 Agent 提高智能或总能提速。
