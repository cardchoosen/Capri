## 剩余收口建议

1. **真机聚焦验收**：一次构建后复用 APK，优先验证第 6–10 项的诊断归属、进程回执、取消、历史修订、后台调度和重启不重放。针对观察到的失败扩展测试。
2. **固定真实任务对照**：固定 DeepSeek 版本、输入、环境与验收产物，比较成功率、总耗时、请求／token／实际费用、重复操作、恢复及约束丢失。先选最近实际失败的 coding、工具发现、长对话和断线任务；不得把合成延时当成真实收益。
3. **专项衔接**：继续独立的 Skill 库与契约迁移，验证现有记忆／经验／版本反馈及本轮执行器兼容，避免第二套技能系统。
4. **实验决策**：根据证据再决定微压缩、辅助模型、SSH、更多语言诊断、全能力后台执行和跨供应商容错；流式／前缀／缓存保持已约定的状态，不自行恢复为必做项。

优先级从“继续加框架”转向“用实际失败任务验证收益、修复回归、完成设备验收”。未通过的真实验收应重新打开相应子项，而不是因已有代码就判定完成。
