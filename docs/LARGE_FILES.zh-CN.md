# Web 大文件输入

2026-11-02。网页的文件选择、拖入与粘贴沿用附件输入流程。普通文件单个上限 512 MiB（536,870,912 字节），每条消息最多 8 个；图片仍受 20 MB 和原有像素限制约束。上传完成仅加入待发送附件，用户发送消息后模型才收到工作区路径、类型和大小，不自动运行文件或上传公共仓库。

## 传输与内存

浏览器使用 File.slice 逐块读取，每块最大 1 MiB，不整份 arrayBuffer 或 Base64。新增同源鉴权 `/api/upload` 二进制入口，保留 Host、Origin、Bearer 校验。HTTP 服务每次最多读取 1 MiB，计算并核对 SHA-256 后转为有界手机桥接帧；Base64 只存在于电脑到手机的单块桥接层。

普通 JSON HTTP 请求仍限制 48 KB；桥接仅 web_runtime/upload_chunk 可使用较大帧，其他方法维持原限制。手机核对会话、应用 epoch、上传 ID、偏移、范围和校验和；SSH、Skill 导入保留各自总量限制和 24 KB 分块兼容。聊天状态与文件操作继续使用独立桥接通道。

手机临时文件逐块写入；同偏移重复块必须与已有字节相同，不重复追加，乱序、重叠冲突或校验错误明确拒绝。导入再次流式复制并计算整份 SHA-256，记录到附件元数据。普通输入允许较大文件，不改变模型 send_file 产物的默认 20 MB 限制。图片检查和视觉压缩保持原约束，不把大图完整编码进模型请求。

## 进度、恢复与取消

上传卡片显示百分比、大小及校验保存状态。分块响应丢失后保留本地 File 对象，用户点击“核对 / 重试”，先查询手机实际接收偏移再继续；已提交的 input_commit 仍通过操作回执核对，不自动重放未知提交。切换对话时在块边界暂停，回到原会话可核对后继续。

“移除”取消本地队列并尝试清理临时上传；若保存已完成，则移除新建待发送附件。取消与写块互斥；正在提交时不删除其源文件。开始上传后才返回 ID 的取消情况也会补做清理。会话与文件作用范围不因重试扩大。

最多同时保留 2 个临时上传，闲置约 20 分钟后可被后续上传清理；开始前按暂存与导入副本预留磁盘空间。断线恢复针对同一浏览器页面、同一应用进程中的上传：刷新/关闭页面丢失浏览器 File 对象，手机进程重启丢失临时上传索引，届时需要重新选择，不能声称跨重启断点续传。完成后的工作区文件及附件元数据按现有会话持久化机制保存。

## 分析与格式边界

大文件只通过路径进入模型上下文；给执行器的英文说明要求先查看元数据，按需分段读取、检索或使用流式解析器。上传成功不代表任意格式都可解析；PDF、压缩包、数据库、日志或二进制等仍由现有工具和任务依赖处理。

## 验证

- UploadChunksTest 检查重复写幂等、错误校验、偏移空洞、冲突及不完整块重叠，拒绝时保持原文件。
- HTTP 定向检查覆盖 1 MiB 二进制转发、校验失败、同源与访问凭证；既有 JSON 请求边界保持。
- 浏览器脚本夹具以有界切片模拟 100 MiB，验证一次响应丢失后按手机偏移恢复，最终只提交一次附件。
- Pixel 8a 实际通过本机 Web 服务与 USB 桥接传入 104,857,600 字节，100 个数据块加一次重复首块，最终 SHA-256 一致；本次上传及落盘约 27.455 秒。该值是本次设备/链路测量，不是其他设备的性能保证，也未测试 512 MiB 整份实传。
- 单个原生用例核对大小、元数据校验和、工作区文件及小于 2 KB 的模型输入清单。只使用独立测试会话和生成内容，随后清理，没有调用真实模型。

构建、精确提交副本检查及部署结果记录于 `work/large-upload/`；本轮不做后台长时间压力测试。

复现定点实传：一端运行 `LargeUploadDeviceTest#hundredMiBFileIsImportedIntactWithoutInlineContext`，另一端运行 `python3 tools/large_upload_smoke.py --serial DEVICE_SERIAL`。需要匹配版本的 Debug APK、测试 APK 和已启动的本机 Web 服务。驱动读取本机访问凭证但不输出，只向原生用例提供的隔离会话传入合成数据；测试会话及文件由原生用例清理。
