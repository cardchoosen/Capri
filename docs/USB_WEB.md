# Capri 电脑网页：连接与自动启动

## 连接链路

电脑浏览器 → 本机 `127.0.0.1:47863` 服务 → ADB USB 转发 → 手机 Debug Unix socket → Capri。

手机仍然保存会话、执行工具和管理任务。电脑网页服务不另存一套聊天历史；服务只监听电脑本机，不开放局域网端口。

## 本次发现与修复

代码中可以确定的连接问题：

- 手机会关闭闲置超过 15 秒的网页 socket，浏览器后台计时器又可能被降频。旧电脑端连接可能在下一次使用时已经失效。
- 旧电脑端重连不会初始化手机 Activity；应用进程重启或 ViewModel 不再可用时，会持续返回 `not_ready`。
- 本地服务原来只支持手动启动，并要求启动时已经有手机。
- 同步、附件和运行管理共用一个串行通道；慢操作可能拖住聊天同步。原先电脑 socket 读取超时 8 秒，网页 API 超时 16 秒，也可能把缓慢响应当作连接中断。
- 原先每次电脑服务启动都生成新访问凭证，旧页面无法继续认证。

本次改为：

1. 服务可以先启动，没有设备时等待；通过 ADB 的设备变化事件检测连接，不持续扫描手机硬件。
2. 只选择已授权设备。自动选择后固定该设备；多台候选设备时要求明确指定，不悄悄切换手机。
3. 连接手机调试入口时，如果应用未就绪，会尝试启动 Capri，并有次数上限和启动节流。不会解锁手机或代替用户授权 USB 调试。
4. 使用前丢弃闲置接近手机超时的 socket，重新取得手机凭证并建立 ADB 转发。
5. 聊天状态同步与下载／运行管理使用两个独立通道，共享固定的设备身份。
6. 调整传输等待时间，保留只读请求的有限重连；消息、历史修改、设置等操作不会因传输失败自动重放。
7. 本机访问凭证以仅当前用户可读写的文件保存，服务重启后仍可使用原网页凭证。手机端临时凭证仍在重连时重新获取。
8. 网页区分等待设备、USB 未授权、多设备、应用未就绪和连接丢失；返回前台或网络恢复时立即尝试同步。

这些是代码层面已发现的恢复缺口，并不能证明所有断开都来自同一原因。USB 线材、电脑休眠、手机系统终止进程等仍可能使底层链路暂时不可用。

## 自动启动

macOS 管理命令，在项目根目录运行：

```bash
# 安装或更新服务；可用 --serial 固定手机。
python3 tools/capri_web_service.py install --serial DEVICE_SERIAL

# 查看是否安装、注册。
python3 tools/capri_web_service.py status

# 再次打开带访问凭证的本机网页。
python3 tools/capri_web_service.py open

# 停止并移除登录自启；保留手机数据和本机凭证。
python3 tools/capri_web_service.py uninstall
```

服务通过用户级 LaunchAgent `ai.capri.web` 在登录时启动。手机不在线时，本地服务继续等待；检测到已授权设备并完成握手后，会自动打开一次网页。重新插线时，已经打开的网页自行恢复同步，不反复新开标签页。

运行文件复制到 `~/Library/Application Support/CapriWeb/runtime/`；凭证与日志在同目录的 `state/` 下，凭证和日志权限为 `0600`。LaunchAgent 文件位于 `~/Library/LaunchAgents/ai.capri.web.plist`。登录自启不依赖后台进程访问项目所在的 Documents 目录。

修改项目里的网页服务或页面后，再运行 `install` 更新运行副本。仅页面资源变化时热更新文件，刷新已有网页即可，不重启服务；Python 运行代码或配置变化才重启。重启时等待旧 LaunchAgent 注销完成，再注册新服务，避免停止／启动竞态。内容未变化且服务已注册时不会重复重启。

仍可手动运行，按 Ctrl-C 退出：

```bash
python3 tools/capri_web.py --serial DEVICE_SERIAL --open-browser
```

## 自动恢复的范围

自动恢复连接、转发和必要的应用启动，不会自动发送聊天消息、重试历史修改、执行旧任务或绕过手机授权。

应用进程重启后，网页会刷新会话与历史修订信息。已经提交但结果不明的操作仍需核对；正在运行的模型任务是否需要继续，按手机保存的检查点处理，不能把网页连上当作任务已经恢复或完成。

## 对话模型选择

网页输入框上方显示当前会话模型和上下文容量，与手机读取同一份配置。点击后按 API 分组搜索模型、查看当前选中项，或进入“管理模型 API”；大列表按 50 项分页，搜索在手机已保存的模型列表内执行，不向供应商发起模型发现请求。≈ 与容量未知的含义与手机一致。

手机切换后，网页随会话同步更新；网页选择也直接保存到手机当前会话。任务运行中仍可选择，新模型从下一轮生效，正在执行的任务继续使用启动时捕获的配置。修改连接失败时保留待核对回执并阻止该会话发送，先读取手机操作结果和当前模型再解除，不自动重放选择。

## 历史消息编辑与重发修复（2026-11-02）

历史用户消息的铅笔按钮在原气泡内打开编辑框，取消恢复原消息，发送沿用历史上下文、版本与请求 ID 校验；重试按选定消息的原文执行，不自动重放未知结果。消息渲染、编辑和取消统一使用 `entry:<稳定消息ID>` 索引，不能用可见序号查找渲染节点。节点不存在时给出提示，不再静默返回。异步读取采用递增请求序号，旧请求不覆盖新编辑框，取消或切换页面后旧错误也不再干扰当前页面。

`node tools/test_web_history.cjs` 覆盖实际分组键、打开/取消、编辑与重发参数、历史版本变化、异步竞态及节点缺失反馈；已有聊天分组与阅读位置检查仍通过。已同步到本机安装的 Capri Web 资源并刷新实际网页，确认编辑框打开、跨轮询保留及取消恢复。未改写或重发真实聊天，没有构建或安装 Android APK。

## 大文件输入

普通文件现支持单个最大 512 MiB，网页采用 1 MiB 二进制分块、校验与进度核对；图片保留原限制。文件落到手机当前会话工作区，发送时只提供元数据与路径。详情、恢复边界及 100 MiB 真机实传记录见 [Web 大文件输入](LARGE_FILES.zh-CN.md)。

## Markdown 附件预览

Markdown 附件新增“查看”，在当前会话打开可关闭的文档子标签，保留对话阅读位置。支持标题、表格、代码块；预览安全边界、大小限制和定稿交付机制见 [报告定稿交付与 Markdown 预览](ARTIFACT_DELIVERY.zh-CN.md)。

## 会话字号

Web 会话右上角提供“字号”，可选小、标准、大、更大四档。聊天正文、工具记录、代码、表格、附件信息、输入区及 Markdown 文档预览统一按比例调整，保留标题和辅助文字的层级。选择仅保存在当前浏览器本机，刷新和切换会话后沿用；默认标准。此功能不修改手机字号或模型配置。

## 新会话默认模型

Web 切换模型时，同时保存当前会话选择和新会话默认选择（API 账号＋模型）。后续新建会话继承该选择，重启后仍保留；手机端新建会话也读取同一份默认值。其他已有会话继续使用各自的模型。旧会话如果此前隐式使用默认模型，会在改变默认值前固定当时的选择；此前未配置或已失效的选择不自动迁移到其他账号。更新在一次配置写入中完成，保存失败不会部分改变当前会话或默认值。运行中任务仍使用启动时捕获的模型。

## 无页面内核接入

Web 冷启动改为启动手机内核服务，不再依赖打开 Capri 页面。应用退后台时由内核待命服务接纳新任务；活跃任务持有必要 CPU 唤醒锁，空闲时释放。用户主动关闭内核后，Web 提示返回手机打开 Capri，不自动撤销关闭选择。权限边界与验收说明见[内核独立专项](KERNEL_INDEPENDENCE.zh-CN.md)。
