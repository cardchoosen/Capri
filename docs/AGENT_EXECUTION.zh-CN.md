# Capri 终端与长任务生命周期

2026-11-02：第七项六个子项的实现与电脑侧验证。手机暂由用户使用，本轮没有连接、安装或操作手机；Android 文件事件、前台服务、进程回收及耗电验收仍待补。本文不把主机测试等同于设备验收。

## 统一登记与归属

`execution/ProcessLedger.kt` 为 `PythonRuntime` 的脚本、argv 短任务、依赖检查／安装、程序内核、代码诊断、MCP 启动器和持续终端统一登记。基础环境的宿主解包与 PRoot 安装也使用该登记；这些安装级进程属于 `installation`，不伪装为某个聊天的任务。HTTP 基础镜像下载沿用已有的大小、摘要、超时及取消检查，它不是一个子进程。

每个启动先持久化 UUID 意图，再启动实际进程；记录聊天归属、执行种类、后端、可执行文件、参数数量、状态、输出位置、取消入口和开始／结束时间。持久终端的每条命令继续拥有独立 `command_id`，并关联父启动器 `process_id`；取消命令和关闭整个启动器的含义不同。原始 argv 不复制到回执，避免额外保存内联代码、凭证和用户内容。实际脚本与已有终端命令预览仍遵循原有任务文件／终端历史策略。

`RuntimeGate` 继续负责维护、共享依赖与删除的互斥；`OwnedProcesses` 继续核验原生启动器身份。登记表不接受模型提供的 PID，不扩大权限，不把 PRoot 当作强安全沙箱。完成只说明实际退出情况，不能证明用户目标完成；中断、启动失败、输出超限及待取消均不能作为成功证据。

`terminal` 新增：

- `processes`：当前聊天最近 16 个启动器回执，包含总数、截断标记及后端状态。
- `process_read(process_id, offset, limit, wait_ms)`：按字节分页读取该执行保留的文件日志和状态；无日志／管道输出明确返回不可用。
- `process_cancel(process_id)`：只停止内存中属于当前聊天的实际启动器。旧回执没有可重新认领的执行句柄。

记录上限 256 条，历史输出预算 64 MiB；下一次启动前逐出最旧的已结束记录，保留运行中的操作。单份完成日志最多保留 2,000,000 字节，超限明确标记，预算可有一个新完成日志的临时增量。聊天删除同时清理登记文件及内存索引；不重放执行。保留的工作区日志与登记表的保留预算相互独立。

## 完成事件与对话交付

Android 管理器通过 `FileObserver` 接收输出／结果／状态文件事件，通过进程 `waitFor()` 接收启动器退出事件。事件通道只保留一个待处理信号，40 ms 合并写入突发；不再闲置时每秒扫描、运行时每 100 ms 扫描全部终端。UI 的持久状态更新与高频输出唤醒分开，避免每段输出重写整个终端日志索引。

`terminal.await(terminal_id, command_id, wait_seconds=300, offset=0)` 挂起当前工具调用，命令完成即唤醒当前执行轮，最长 300 秒，不消耗额外模型请求。返回执行状态和同一套有上限的输出页；时间到仍在运行时返回 `wait_expired`，不伪造完成。已有 `run` 的短等待和 `read` 的可选等待也改为事件唤醒，保留原有等待上限及 flat／legacy params 兼容性。

用户停止等待只取消当前调用，不关闭持久终端。用户补充新要求会唤醒等待，使执行尽快回到接入纠正的安全边界；已运行的命令不因此自动回滚。每次模型准备上下文时加入当前聊天最多 4 个终端、每终端最多 2 条命令的状态快照，模型无需重新探索所有终端。

这不是后台任务调度器：应用被 Android 杀死后不会自动启动模型、重建 shell 或继续未知副作用；没有等待中的执行轮时也不会额外付费唤醒模型。此类持久目标调度属于第十项。Python PTY 监督器仍有 50 ms 的控制／截止时间循环，短任务仍保留取消与输出安全检查；本次消除的是管理器和模型层的重复无变化查询，并未宣称整个运行栈没有任何定时检查。

## 独立完成回执与重启

启动器回执保存在 `process-ledger/<chat>/<uuid>.json`，由临时文件、文件同步和原子替换发布。完成时先冻结该执行的文件输出再发布完成状态；清理临时运行目录或复用原日志路径不会让旧 ID 读到后一次执行的日志。`OwnedProcesses.stop` 与自然退出事件共用幂等完成钩子，避免执行者清理文件早于回执捕获。写盘失败通过 `receipt_durable=false` 或 `output_capture_failed` 暴露，不假装结果已经完整保存。

重启时未完成的启动器转为 `interrupted / effect=unknown`，不按照 PID 或旧句柄重新附着，也不重试命令。已经落盘的完成／失败回执保留实际状态。结果文件缺失仍可能代表“实际结束但未记下”，不能据此判定从未执行。

终端命令结果独立保存，包含 `terminal_id`、`command_id`、实际结束时间、退出码和原因；输出关闭前同步，结果文件原子发布。新版命令只认领两种 ID 均匹配的结果。旧版本命令仍按原有受聊天范围约束的目录协议读取，保持升级兼容。

## 输出分页、背压与取消

`execution/OutputPage.kt` 为持续终端和统一进程日志提供相同的 `offset / next_offset / total_bytes / has_more / complete / output_available`。默认 16,000 字节，最大 32,000 字节，并额外限制 JSON 转义后的文本预算。UTF-8 尾部不足一个字符时不消费该尾部，下次继续；读取不吞掉流，也不自动从头回放。

终端监督器继续严格限制命令与总转录各 2 MB；普通重定向文件超限通过文件事件停止启动器，原有执行路径也保留安全检查。文件事件并非内核写入配额，停止前可能短暂超出阈值；完成日志只保留有上限的前缀并报告截断。持续内核／MCP 的协议管道由原协议消费者独占，不能为了统一日志读取而偷读协议或伪造可分页输出。

`complete=true` 只表示执行结束，不表示已读完；未读页由 `has_more` 指示。非零退出、取消、超时、输出超限与中断必须分别解释。`terminal.cancel` 中断一条命令并按原机制检查 shell 是否可复用；`process_cancel` 关闭整个启动器，其子树仍沿用已有 PRoot 清理约定。

## 环境后端评估

`ExecutionBackend` 抽象启动与结果身份，本轮落地 `local_proot` 和安装器专用 `local_host`，与上述同一登记／回执／输出协议结合。模型没有新增任意后端或目标地址参数。

SSH 评估结论：现有 SSH 命令可作为本地终端中的客户端，但不能据其本地退出码声称远端任务完成或取消。可靠 SSH 后端还需要明确配置的目的地与凭证作用域、远端任务 UUID 和持久结果、输出续读、断线后的未知状态及远端取消回执。本轮对 `ssh` 返回明确不可用，不悄悄退回本地执行，也没有接入或测试任何远端主机。这完成的是第 7.5 项要求的抽象与评估，不是 SSH 执行后端交付。

## 环境事实复用与失效

已有环境档案仍按设备／共享 Ubuntu／单聊天 venv 的作用域、TTL、启动标识、探测版本、网络元数据和实际观察文件决定复用；没有新增启动时全量探测。

新增 `EnvironmentStamp`：小于等于 256 KiB 的已观察文件与项目清单除路径、大小、时间外还核对内容摘要，避免等长修改／保留时间戳让旧证据看似有效。读取有硬上限，目录及大文件保留元数据检测，不递归扫描整个依赖树。外部大文件保留所有元数据的修改仍可能无法即时发现，必要时使用已有强制 refresh／实际 verify。

任意 shell 与脚本不能仅凭命令字符串可靠判断只读，因此终端命令、Python 脚本和通用 argv 执行在开始及结束时保守失效共享／聊天依赖事实；准备依赖继续沿用已有的作用域失效及实际检查结果归档。正式环境检查和代码诊断不一律失效缓存。这用部分缓存命中率换取未知副作用下的正确性，不宣称所有脚本之后都能零成本复用环境证据。

## 验证

电脑侧：精确待提交源码独立构建 Debug APK，41 个相关 JVM 检查通过；这些检查覆盖真实子进程非零退出、事件等待与等待取消、聊天隔离、重启未知状态、持久输出快照、输出超限、环境失效时机、保留时间戳的清单修改、后端拒绝及错误完成证据。复用终端契约、UTF-8 分页、运行互斥、环境档案及 Agent 核心检查。

实际 Python PTY 监督器 6 个主机回归检查通过：工作目录／变量／函数保留、交互输入与中断复用、超时和 Unicode、嵌套交互 shell、拒绝中断时关闭终端、两个日志的硬上限；所有命令同时核对完成回执的两个 UUID 和结束时间。

主机不能验证 Android inotify 投递、前台服务限制、后台唤醒锁、真实 PRoot 进程树取消及进程死亡窗口；也未做真机耗电、真实模型费用／等待延迟对照或 SSH 远端测试。设备可用后只补相关核心场景，不把这些未做检查计为通过。
