# Capri 工具发现与能力感知

> 2026-11-03：工具注册、发现、契约装配及公共参数校验已迁入独立 `agent-core`，具体派发和权限仍由宿主处理。见[内核独立专项](KERNEL_INDEPENDENCE.zh-CN.md)。

2026-10-30，对应优化待办第 4 项。本轮六个子项完成首版实现：统一契约快照、能力状态、核心工具直供、多查询检索、专用工具桥接和有界定义工作集。这里只描述已实现机制与聚焦验证，不把它等同于真实模型上的最优路由或提速结论。

## 同一份契约快照

`ToolRegistry` 从当前内置定义与本会话已连接 MCP 的原始定义生成快照。重复名称出现冲突契约时拒绝注册；调用方修改输入对象或取出的定义不会改写注册表。工具目录 `ToolsCatalog`、发现层及调用前校验共用这条路径，现有工具标识、执行后端和显示名称回调保持兼容。

第一方调用先做公共形状校验，再走原工具的动作校验、权限、文件租约和作用域检查。公共校验支持类型、必填、枚举、长度、数值边界、对象字段、数组、组合分支与本地引用；不是完整 JSON Schema 实现，工具后端仍有最终校验职责。导入的 MCP Schema 原样保留，沿用现有传输／服务端校验语义及 128000 字符参数上限，避免用不完整的客户端校验器误拒绝第三方契约。

## 可用状态与核心工具

Android、浏览器、文件、coding 和执行工具直接提供定义，不必先搜索加载 Android/browser。`callable` 只表示存在可派发入口，不保证动作权限、依赖或任务效果；具体权限与环境条件仍由原执行后端检查，不新增预授权。

模型可见目录同时提供已配置 MCP 服务状态：

| 状态 | 含义与下一步 |
| --- | --- |
| callable | 连接、配置、会话激活和目录状态可用于派发，搜索实际工具名称 |
| activation_required | 配置存在，按用户任务授权通过 extensions.activate 连接 |
| reconnect_required | 当前连接不可用、配置或工具目录已变，需要再次激活刷新 |
| credentials_required | 已知必需凭据缺失，在运行设置中配置 |
| disabled | 服务未启用，在运行设置中启用 |

配置描述不包含 Token、请求参数或原始连接错误。服务状态读取不会连接、安装依赖或调用外部服务。目录最多展示 40 项延迟工具与 24 项服务，并明确省略数量；搜索仍覆盖当前完整快照。工具 schema 可用不表示所有动作已获授权；权限只在执行路径核验。

MCP 的定义、能力状态和实际调用共享连接／配置门槛，包含会话激活、进程存活、断开、凭据、配置版本和目录变更。模型请求重新核对清单；发现、桥接和 MCP 调用前还会刷新，处理同批调用之间的撤回。静态内置定义复用本轮快照，避免每次文件读取都重复扫描 MCP 配置。

## 检索与定义工作集

`tool_search(query, limit)` 保持兼容；新增 `queries` 接受最多 4 个替代查询，与 query 二选一。默认返回 4 项、最多 8 项。检索采用名称优先、词形归一及有限的中英文同义词映射，覆盖设备、网页、环境、文件、记忆、仓库等常见领域。没有额外模型或网络检索，也不是任意自然语言的语义检索。

结果区分 tools 与 configured capabilities。仅找到未连接服务时返回 capability_found 及下一步，不伪造可调用工具。not_found 只代表当前清单未命中，不能据此断言能力不存在。`tool_describe(names)` 继续按已知名称加载定义。

延迟定义使用 LRU 工作集：默认最多 8 项，独立构造时预算为 8000 个原始估算 token；实际运行按初始模型输入预算的四分之一设置，限制在 256～8000。核心定义、发现入口、目录及普通消息另计入既有整体上下文预算。加载／实际使用更新最近使用次序；过量时淘汰旧项；撤回或契约变化会撤销已加载状态。

超大定义或同批请求无法容纳时显式返回 refused 原因，不把超大 schema 塞入结果，也不自动扩大预算。重新 describe 可再次加载，或者在确知契约时走桥接。核心定义本身不会被裁剪；模型容量不足时仍按上下文预算显式失败。

## 专用工具桥接

新增英文契约 `tool_invoke(name, arguments)`，arguments 为对象。目标限定为已知第一方专用工具或本会话已连接的 MCP 工具；拒绝嵌套调用、控制入口、核心工具和未注册目标。不按模糊搜索结果自动执行，也不自动激活、重试或重放。

桥接解析目标后进入原 `CapriModel` 执行分支。已有参数校验、权限检查、会话作用域、取消、工具租约和恢复逻辑继续适用。供应商记录保留原始 tool_invoke 调用与调用 ID，结果仍对应这个 ID；界面标签、完成证据、收尾筛选及停滞判断按实际目标解释。

知识／记忆参数和结果沿用检查点脱敏；桥接知识检索在资料删除后同样刷新，环境查询也沿用旧结果更新机制。MCP isError、未知执行结果及调用失败不会作为成功证据。读到检查点不会重放操作。

确知契约时可以省去一次“先加载定义、再请求模型调用”的往返；不知道参数时仍需 search/describe。当前入口已接入执行，但尚未证明 DeepSeek 会稳定选择最优路径，或所有任务总耗时会减少。
