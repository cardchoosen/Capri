# 文件、图片输入与网页工具折叠

## 当前行为

- 手机对话页的“＋”提供“选择图片／选择文件”。选择后，输入栏上方显示文件名、大小、图片缩略图与移除按钮；点击发送才进入会话并发起模型请求。文件页的“导入”继续只导入工作区文件。
- 网页提供“＋”选择、拖入文件和粘贴图片，显示上传进度、待发送附件与移除入口。手机和网页读取同一份会话附件草稿。
- 每次最多选择 8 个非空文件，单个原文件不超过 20 MB。原文件保存在当前会话 `workspace/inputs/<id>/`，同名文件使用独立目录，不覆盖已有文件。
- 普通文件作为有名称、类型与路径的输入交给 Capri，通过合适的文件／执行工具读取。上传成功不代表所有文档、音频或视频格式已经具备解析能力。
- PNG、JPEG、GIF、WebP 图片支持直接视觉输入；模型／接口也必须支持视觉。GIF 等动画提供首帧，原始文件仍保留。图片在发送时按比例缩至最长边 1536 像素，透明背景在视觉副本中铺白，再编码为有大小上限的 JPEG；不改写原图。
- 最多将最近 8 个输入图片引用放入视觉请求。更早的图片保留工作区引用，并在请求中明确说明未内联。

## 消息与恢复

用户消息保存附件元数据、文件路径与 SHA-256，不在聊天、检查点或性能日志中保存图片 Base64。图片字节只在发出请求时装载，并适配 Chat Completions、Responses、Anthropic、Gemini 四种既有协议。准备图片时核对文件摘要；文件变更或无法解码会明确失败。

已发送附件会从待发送列表移除，但原文件保留。历史编辑／重试沿用原消息的附件引用，不混入后来新选择的文件。进程中断后，已持久化消息中的附件不会再次出现在草稿中；删除会话也会清理对应草稿索引。

网页上传分为准备、按偏移写块、提交到附件草稿。每个块有明确偏移；重试先读取已接收进度。开始／提交使用请求回执核对，连接失败不自动重放未知操作。应用重启导致上传状态不明时，保留需核对的本地选择；用户先检查手机附件列表，再移除或重新选择，不静默漏发。

模型是否接受视觉请求仍取决于具体型号、供应商和代理接口。本轮验证了客户端协议与图片装载，没有把所有已配置模型逐一做付费视觉验收。

## 工具过程显示

网页由手机的 `timelineRows` 提供整轮执行过程归属，默认折叠中间说明与工具记录，保留最终回复、附件及失败状态。展开整轮后，各项工具输出仍默认折叠，显示与手机一致的工具名称及异常／授权状态；展开后可查看、选择和复制原始输出。

用户上传的附件位于用户消息之后、执行过程之前；Capri 生成的附件仍在执行过程之后展示。发送侧附件明确标注“你发送的附件”。
