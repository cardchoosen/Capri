# 可靠性、长期运行与评估

2026-11-02：第十项六个子项的首版实现。复用现有检查点、模型传输、文件隔离与委派控制器；本轮只做电脑侧开发和验证，没有连接或操作手机。

## 10.1 会话、压缩与恢复的来源链

`agent-events/<chat>/journal.json` 保存统一元数据事件。检查点的 `_capri_lineage` 保存当前节点、检查点内容哈希、所属历史作用域和转换类型；下一个节点引用前一个节点。恢复会创建 `resume` 节点，压缩节点关联原始归档 ID，历史编辑事件记录原上下文与旧检查点节点。

来源链描述状态来源，不回滚文件、进程或外部副作用。节点先写事件，再写原检查点：进程中断可能留下未被检查点引用的事件；以实际已发布检查点内的节点为准，不能凭最近时间戳猜测状态。完全相同的检查点不重复产生节点。

每聊天保留最近 512 个事件，每次最多读取 64 个。序号跨该聊天的历史作用域递增；返回值明确标记 `gap`，不把被回收的旧记录伪装成完整历史。节点链可能越过保留窗口，属于来源不足，需要查原始聊天／归档。日志不存提示词、工具参数／正文、密钥或命令输出。

## 10.2 模型与辅助调用的独立容错

继续只在模型传输层重试；工具调度不随网络重试重放。总请求上限保持 50 次，压缩默认最多 6 次、交付最多 3 次、委派最多 8 次；重试计入对应用途和总预算，正常执行仍保留原有交付容量。每个用途独立统计失败、尝试和上限，辅助调用失败不会消耗另一个用途的独立计数。

不是额外赠送请求：总预算与父任务保留容量仍有约束。无效格式、鉴权、TLS、上下文拒绝沿用原有禁止盲重试边界，较长 `Retry-After` 留给显式接续。取消仍中断传输。

当前只有已配置路线，`fallback_policy=same_config_only`，没有自动换供应商、账号、协议或数据目的地。后台任务保存现有模型配置指纹；模型、接口、协议或密钥变化后转为 `needs_review`，重新创建才采用新配置。费用不明时保持未知，不根据 token 数编造金额。备用路线仍需未来有候选配置及能力／质量／目的地对照后再实现，不把路线评估写成已上线备用模型。

## 10.3 持久目标与 Android 后台续作

`agent_jobs` 提供两种有明确边界的目标：

- `checkpoint`：通用长任务的持久目标。保留创建消息、原始用户要求、检查点来源和所属历史作用域；就绪后由前台主任务核验实际状态再继续。`complete` 必须引用本任务已记录的积极工具证据，并通过现有任务计划／完成检查。保存或触发本身不是用户目标完成。
- `analysis`：针对 1–16 个精确 UTF-8 工作区文件的隔离只读分析。复用 `DelegateEngine` 的文件快照、项目规则、结构化结果及原文证据；全应用最多一个持久分析、120 秒截止时间、最多四轮子推理，网络重试与委派预算均受原有控制器限制。

两者保存原始用户约束账本，超过 8000 字符拒绝交接，不静默丢掉纠正。后台分析不继承整个聊天、长期记忆、Skills、Shell、手机、浏览器、账号、MCP、文件写入或继续委派能力，不会后台部署或修改用户文件。需要这些能力的一般任务保留前台接续路径。本轮未实现任意全能力 Agent 的自动后台恢复。

默认 `allow_background=false`。只有用户明确授权无人值守模型分析时才设置为 true；前台显式 `run` 可以执行未授权后台的分析。前台执行使用当前主任务请求预算，后台使用独立 8 次上限，并受到全应用模型并发与子任务预算约束。依赖服务端的已开始计算不承诺退款。

Android `JobScheduler` 负责延迟／周期唤醒，周期下限 15 分钟；有预计时间的分析登记最早可运行唤醒，周期核对作为后备。任务身份、发生次数、运行 ID、结果和去重由应用自己的原子存储负责。每次系统唤醒最多执行一个发生项，错过周期合并为一次，不补跑欠账。系统可以推迟、停止或限制后台任务；强行停止应用后不能承诺继续运行。

发生项在模型请求前持久标记 `running`。重启发现没有对应活跃执行时标记 `interrupted`；不自动重放未知运行、不把 PID 当恢复凭证。一般前台任务继续沿用检查点恢复时补齐未知工具结果并先核验的机制。

## 10.4 定时及事件触发任务

同一个工具提供 `create/list/read/run/pause/resume/cancel/complete/events`：

- `manual`：保存后就绪，由前台显式处理。
- `once`：Unix 毫秒的最早到期时间，最多提前一年。
- `interval`：15 分钟至 30 天，上一发生项结束后计算下一次，不重叠追赶。
- `event`：创建之后的 `process_completed`、`coding_ready` 或 `turn_finished`；可按精确来源 ID 过滤，首次匹配后消费为一次。

进程事件只在完成回执持久保存后发布，当前沿用进程登记的聊天归属；它没有历史修订信息，因此不自动跨到已编辑历史作用域。代码诊断和主任务事件携带原执行作用域。历史被编辑后，旧作用域后台分析不会继续派发到新时间线。

事件游标防止旧事件重触发；保留窗口有缺口时转 `needs_review`，不猜测事件是否发生。创建通过作用域内 `request_key` 和规范化参数哈希去重；冲突明确拒绝。每聊天最多 128 份任务，保留小型身份与结果回执，不靠删除去重记录腾空间。后台分析同时继承委派记录的容量上限；达到容量会明确失败／待复核，不能宣称无限期免维护运行。

暂停／取消递增运行代次，在安全边界停止后续派发；运行中的模型等待会被本地状态事件中断，无每秒轮询。回执仍保留已发生的请求与结果，不回滚既有副作用。连续三次周期失败转待复核，不无限收费重试。`resume` 仅重新启用暂停任务；中断、失败和过期配置的处理需要显式核验。删除聊天或重置共同经历先取消／等待相关分析退出，再清理目标、事件与原有检查点；重置同时取消系统调度。

## 10.5 手机、Web、日志与扩展的统一事件

事件 schema 由 `AgentEvents` 统一定义：作用域、序号、事件 ID、时间、种类以及有限的状态／来源元数据。已接入主任务开始、阶段、工具意图／结果、结束、检查点、恢复、压缩、历史编辑、代码诊断、进程完成与持久任务回执。

手机的“持久任务与执行来源”、Web 的“持久任务”和 `agent_jobs events` 使用同一数据源。Web 的只读 `web_events` 沿用现有调试桥鉴权和历史作用域检查，不增加外部未授权入口；面板按用户打开读取，没有新增持续轮询。任务结果通过 `agent_jobs read` 和原有委派证据分页读取，后台不把消息伪装成用户插入对话。

这是元数据事件扩展接口，消费方可用序号、缺口与来源 ID 建立投影。未开放让第三方任意注入任务事件或绕过权限的插件回调；现有 MCP 和原生工具执行规则保持不变。事件不是重复运行命令，也不能仅凭 `returned` 判断任务成功。

## 10.6 固定任务与轨迹回放

`tools/fixtures/agent_reliability/cases.json` 固定六种轨迹：文件交付、未知副作用恢复、压缩保留约束、只重试模型、等待外部事件和取消边界。`tools/agent_replay.py` 无网络、无工具执行，校验顺序、意图／结果、重复效果、预期状态、产物哈希、约束哈希和请求预算，报告耗时、调用数、已报告 token、缺失 usage 及未知费用。

比较同时固定模型、协议、环境与夹具版本；身份不一致标记不可直接比较。哈希校验与预期结果由夹具声明，只证明这些声明的可重复约束，不构成真实用户任务或智能提升证明。回放本身绝不重发轨迹里的工具调用。

运行方式：

```sh
PYTHONPATH=tools python3 -m unittest tools/test_agent_replay.py
python3 tools/agent_replay.py tools/fixtures/agent_reliability/cases.json --output /tmp/capri-replay.json
```

JVM 核心检查额外执行真实文件隔离／委派控制器、目标状态机、事件存储和模型预算，覆盖跨历史隔离、配置变更、暂停取消、崩溃不重放、周期合并和事件缺口。Web 主机回归使用模拟桥接，不访问设备。
