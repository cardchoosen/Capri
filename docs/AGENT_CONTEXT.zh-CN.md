# Capri 上下文管理

本轮对应 Agent 优化待办第 3 项，完成六个子项的首版实现。目标是让压缩可替换、约束可保留、原始证据可找回，并保证摘要失败不破坏执行检查点。微压缩与知识候选仍是受控实验，尚未证明真实模型上的质量和速度收益。

## 策略与运行路径

`ContextHistory` 接受 `ContextStrategy`。默认 `PressureContextStrategy` 在估算输入达到可用预算的 85% 时尝试压缩，预留约 20% 余量；无法取得余量时以实际预算判断。未达阈值且预算足够时不调用摘要模型。模型输出、工具定义和运行时任务状态继续沿用既有预算预留，估算值不等于供应商 tokenizer 的实际用量。

`ContextWindow` 只负责选择可移出的消息，没有文件写入或工具执行。`ContextHistory` 持久化原始片段与交接档案后，再调用已有摘要路径；默认仍使用当前模型，不添加供应商或后台请求。摘要请求继续计入 compression 用途及请求预算。

保留同步 `fit` 提取式回退与既有分页查询。空白、超长、超预算摘要或取消不会替换已发布摘要，也不会修改调用方的消息数组；未发布的原始归档和交接档案可能留在当前会话范围中，以便恢复。压缩本身不保存或重放外部工具操作。

## 用户要求与完整交互

当前任务的原始请求与后续纠正逐条原文保存在检查点 `instructions` 中，由运行时追加，模型不能通过 `task_state.update` 改写。旧 `user_context` 的最近 12 条视图保留兼容，发给模型的任务状态使用完整 instructions，避免重复发送这个短视图。旧检查点会迁移仍然存在的纠正；迁移无法恢复历史上已经丢弃的信息。

原始首条、最新用户消息及当前任务起点之后的所有用户消息保留原文。消息 entry ID 用来识别真正的任务起点，避免相同文本重复出现时误判。归档使用内部元数据区分，并预留辅助快照标记；用户输入相同的“Capri”前缀不会因此被删除。可移植历史保留这些内部标记，四种供应商请求格式均不发送内部字段。

工具调用和对应结果成组移出，并保留最近一组。检查成组调用 ID 与结果 ID 是否唯一且完整匹配；缺失或冲突时停止压缩，保留检查点，要求先核实效果。约束和最近交互本身超预算时明确失败，不静默裁掉约束。已经归档的完整证据可读回，不能因为摘要没有提到就重新执行有副作用操作。

## 大结果预览

原始结果先写入 `r` 归档，再产生受长度限制的 JSON 预览。现有 Skill、知识和记忆工具的特殊处理保持不变。

| 类型 | 重点保留 |
| --- | --- |
| 执行日志 | 状态、退出码、嵌套错误、命令/终端标识、首尾诊断 |
| 网页与搜索 | URL、标题、citation、source_id、片段、分页位置 |
| 文件读取、列表与搜索 | 路径、行列、sha256、分页坐标、有限数量的条目或命中 |
| 其他结果 | 已知状态与元数据、有限正文、首尾摘录、原文引用 |

预览显式标记截断，数组记录省略数量，原始 reference 另存 source_reference，归档 reference 用于回读。`result_incomplete` 继承原始失败或待定信号，避免删除中间字段后被完成检查误判为成功。预览不等于完整证据；极小的预览预算或超大结构可能退化为首尾和归档引用，完整信息需分页读回。

## 微压缩实验

`MicroContextStrategy` 只能显式注入，产品默认不开启。硬预算尚能容纳输入、估算输入达到 65%，并抵达新的用户消息边界时，最多摘要一个旧组；相同边界不重复摘要。硬预算溢出时仍走压力压缩。边界优先使用 entry ID，缺失时使用文本摘要，不额外保存整份用户文字。

测试验证了一组/一次边界的调用上限和上下文缩减。尚未进行真实 DeepSeek 对照，因此不能宣称减少用户等待；额外模型调用、摘要失真、缓存损失及真实费用需要后续固定任务比较。

## 压缩前交接与知识候选

新增 `h` 交接档案，写入时间早于摘要调用。内容包括请求、完整纠正、计划、agent findings、工具证据索引及原始 `c` 归档引用。候选经验来自已有 findings，标为 `unreviewed_task_local`，没有自动知识判定或验证。计划与 findings 都是 agent 陈述，不能当作验证证据。

这些数据沿用会话及历史修订的隔离、删除和重置语义，可通过 `context_history(reference=h...)` 分页读取。不会自动写入 personal_memory、KnowledgeStore 或 Skill，也不会因压缩把暂时结论提升为长期事实。后续记忆与 Skills 专项再讨论授权、筛选和验证后的推广路径。

## 验证与限制

本轮新增 13 个 JVM 用例，通过了纠正保留、旧检查点迁移、摘要失败/取消、完整多工具交互、来源与文件版本预览、作用域隔离、微压缩去重、超预算保护和四种供应商私有字段过滤。已有 ModelContextTest、AgentHarnessTest 与 TurnControlTest 在本轮相关实现上通过。

真机用例 `ContextManagementDeviceTest#compactionRecoveryAndFullResultRemainScopedAndReadable` 使用独立缓存目录、真实 AtomicFile、AgentRecovery 和固定摘要，验证 20 条纠正恢复、归档分页、跨会话拒绝、失败预览及摘要失败后的检查点保留。没有真实供应商请求，也不更改用户会话。

真机固定样本：输入估算从 20,993 降至 3,608（约 82.8%），固定摘要回调 1 次，本地整理耗时 57 ms。此数字只描述人工构造样本的本地处理，**不含真实模型摘要延迟，不能视作端到端性能基准**。通过报告：`work/verify/20261030-154412-389159/report.json`；13 项 JVM 新用例报告：`work/verify/20261030-154327-665078/report.json` 中 Gradle 步骤（该次设备夹具随后修正并通过上述独立报告）。
