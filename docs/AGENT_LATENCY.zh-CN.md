## 分阶段耗时归因

沿用 PerformanceTrace 与 `tools/analyze_agent_run.py`，新增 `tools/agent_timing.py` 作为归因模块。

- 每个模型请求、响应头、正文接收、解析、重试等待都有 `execution`、`compression` 或 `delivery` 用途标签。
- `model_prepare` 记录图片装载、协议组装及正文序列化时间；`model_queue` 通过 OkHttp 应用拦截器记录从派发到工作线程开始的等待，不包含后续 DNS 和建连。未经过该拦截器的客户端不报告排队值。
- `turn_prepare` 覆盖初始 Skills、检查点与环境等准备；`context_prepare` 覆盖每轮工具与上下文准备；`delivery_prepare` 记录直接交付判定及人物收尾输入组装。
- `delivery_route` 区分人物收尾与纯 JSON 直接交付。
- 记录继续只包含固定枚举、计数、耗时和供应商用量，不记录提示词、模型原文、URL 或凭据。没有真实价格时不推算费用。

分析命令仍使用既有入口：

```bash
python3 tools/analyze_agent_run.py metrics.json --trace --output timing.json
```

输出保留既有字段，并新增 `attribution`：

| 字段 | 含义 |
| --- | --- |
| `wall_ms` | 将观察到的总时间分配给收尾、摘要模型、执行模型、用途未知模型、重试等待、工具、准备及其他；不重复相加。 |
| `nested_union_ms` | 各细分阶段的时间并集，供钻取；不能再加到总时间上。 |
| `model_attempts` / `unsuccessful_attempts` | 各用途的客户端请求尝试及未成功尝试。 |
| `usage_by_purpose` | 从模型解析事件汇总供应商返回的 token 用量。 |
| `queue_measurement` | 有排队记录的尝试数量及覆盖率；缺记录不等于等待为零。 |
| `delivery_routes` | 两种交付路径出现次数。 |

人物收尾内部的请求归入收尾，不再重复算到执行模型；多个工具同时执行按时间并集计算。并发跨类别采用明确优先级归因，不等于证明某阶段是性能瓶颈。旧记录缺少用途标签时保留为用途未知；没有任务结束事件只表示已观察前缀。响应头到达也不等于模型第一个 token 到达。

历史单例重新归因后，Android 烟测的 9,006 ms 中人物收尾为 1,457 ms；coding 接续的 9,479 ms 中收尾为 4,331 ms。这是旧单例的归因，不是当前 DeepSeek 性能基准或优化后提速数据。材料在 `work/agent-latency/2026-10-30/`。

## 人物收尾优化

### 明确纯 JSON 请求的直接交付

`agent/DeliveryPolicy.kt` 仅在以下条件成立时复用已有草稿，跳过人物收尾请求：

- 原始任务明确要求只输出 JSON；仅提到 JSON 不算。
- 草稿是通过严格解析与值检查的 JSON 对象或数组；不含 Markdown 围栏、尾随说明、非法字面量等。
- 本轮没有接入中途纠正，且没有部分完成或阻塞评估；旧检查点缺少相应元数据时保守回退。

返回原始 JSON 文本，不转成浮点数再序列化，保留大整数和原始数字表示。普通对话、无效 JSON、不明确格式或需要重新判断的情况继续使用 Capri 人物收尾。该路径也沿用交付前的补充消息检查和完成检查点，不重跑工具。

这只能保证省去符合条件场景的一次收尾请求，不能保证所有任务整体更快，也不保证 JSON 里的事实天然正确。

### 减少收尾输入里的重复管理记录

交付包不再把计划、工具发现、澄清及模型信息等管理结果挤入工作证据列表；任务状态仍单独保留。优先保留已知失败和交付评估引用的工作结果，再补充近期结果。嵌套命令失败也按失败保留，避免根状态为 `ok` 就被忽略。

用户人格文案、普通对话的独立人物表达和模型配置保持现有行为。本轮没有启用辅助收尾模型或降低全部回复的输出上限。

## 辅助模型离线验证

`tools/auxiliary_summary_eval.py` 提供三个合成样例：验证失败、崩溃后副作用未知、权限边界。导出时只提供输入记录和英文任务说明，不导出参考答案。

```bash
python3 tools/auxiliary_summary_eval.py export work/auxiliary-prompts
python3 tools/auxiliary_summary_eval.py grade candidate.json
```

候选结果为按样例 ID 索引的 JSON 对象。机械检查核对约束、来源、路径、失败／未知状态和剩余任务；另外必须人工检查目标与自然语言摘要是否正确、是否编造成功。通过机械检查不能自动启用模型，也不代表语义摘要质量通过。后续真实候选对照还需记录模型版本、延迟、用量及实际费用来源。

当前未调用真实 DeepSeek 做对照，未新增模型配置或自动分工。离线夹具就绪不等于辅助模型分工完成。
