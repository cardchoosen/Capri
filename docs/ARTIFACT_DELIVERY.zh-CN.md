# 报告定稿交付与 Web Markdown 预览

## 定稿后交付

`send_file` 默认使用 `delivery=final`：工具成功表示文件已经进入本轮交付队列，不表示用户已经收到附件。Capri 应先完成分析、修改和必要检查，再登记最终版本；同一路径重复登记只保留最后一次，单轮最多八个文件。

框架在任务最终回复阶段核对源文件内容，生成独立文件快照，等最终回复成功后一次展示附件。登记后又改了文件，会要求重新检查并登记，不能交付过期版本。已经交付的附件引用快照，之后修改工作文件不会覆盖历史附件。已有历史重复附件不删除，也不能据此恢复此前被覆盖的旧版本。

队列随现有检查点保存，中断后可继续；用户修改需求会清空待交付队列，必须依据新要求重新检查。快照使用稳定交付 ID，恢复后不会因重复发布增加相同附件。只有用户明确要求中间结果时才使用 `delivery=preview` 即时发送；正常修改报告不使用这个选项。这里的“确认”是任务内检查，不增加用户确认弹窗。

输出文件仍遵循原有单文件 20 MB 限制，与 Web 大文件输入的 512 MiB 限制不同。

## 会话内预览

Web 的 `.md`、`.markdown` 或 `text/markdown` 附件显示“查看”。点击后在当前会话创建文档子标签，可在“对话”和多个文档之间切换，关闭标签不会删除附件。对话阅读位置和各文档滚动位置分别保留，同一附件重复打开复用标签。

预览复用经过鉴权的附件读取接口和现有 Markdown 渲染器，支持标题、表格、代码等。原始 HTML 作为文本显示，不执行脚本，不加载文档中的外部图片。预览仅接受 UTF-8 文本，单文件最多 2 MiB；超过 250000 字符或 5000 行时明确提示只展示前段，完整文件仍可下载。错误时可以重新读取。

标签按会话、上下文和历史版本隔离，切换会话不混用文档；会话重置、历史改写及删除会话后释放对应内容。每会话最多六个文档标签，全局最多二十个。标签仅保存在当前网页内存，刷新后需重新打开。

## 验证

聚焦检查覆盖：暂存期间不交付、修改后要求重新登记、同路径替换、最终快照独立于后续修改、重复发布去重、检查点保存和用户改需求清空队列。网页检查覆盖安全渲染、表格与代码、重复打开、阅读位置、会话隔离、关闭释放资源和预览大小限制。未通过真实模型反复生成报告来验收，不改写用户真实聊天。

验收记录（2026-11-02）：独立提交源码的 Debug APK、测试 APK 构建和 28 个相关 JVM 检查通过；`ArtifactDeliveryDeviceTest#onlyLastCheckedRevisionIsPublishedAsAnImmutableSnapshot` 真机检查通过。首次真机检查发现 Android 数据目录别名影响快照相对路径，改用规范目录后重跑通过。`test_web_documents.cjs`、`test_web_history.cjs`、`test_web_reading.cjs` 通过；实际 Chrome 合成报告确认“查看”打开子标签、标题/表格/代码渲染、返回对话与关闭。手机保留数据更新，本机 Web 服务资源同步。记录与合成截图位于 `work/artifact-preview/`（不提交生成物）。
