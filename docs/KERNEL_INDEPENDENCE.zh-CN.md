# Capri 内核独立专项

## 专项目标

Capri 复用同一套 Agent 内核，支持两种部署方式：

| 模式 | 任务和会话由谁管理 | 客户端 |
| --- | --- | --- |
| 手机本地 | Android 运行宿主负责执行、存储和恢复。界面关闭或重建后，仍可接回宿主中的任务。 | Android UI；现有 USB Web 入口可继续访问本地宿主。 |
| 服务器 | 独立 JVM 服务在服务器上执行任务，管理会话、工作区和工具。手机离线或关闭页面后，服务器继续运行任务。 | Android UI 和 Web 连接同一服务，可以进入同一会话、查看进度和取消任务。 |

已决策：Android 过渡期保留双模式，用户在设置中显式选择本地或服务器模式。服务器离线时，可切换到本地宿主继续运行本地任务。新增 Agent 能力和强化面向服务器模式，本地内核保留现有能力并做必要的兼容与修复，后续逐步退役。退役范围是 Android 本地 Agent 内核及其运行宿主，届时 Android 仍可作为云端客户端和被控设备。本地和服务器各自管理会话、历史、工作区及任务。切换模式只切换当前连接的宿主及其会话列表。已有数据留在创建它的宿主，不提供迁移、同步或跨宿主续跑。升级后首次打开默认进入本地模式，后续启动记住用户上次选择。远程模式通过配置的 Capri 服务地址和网络协议接入；客户端设置、文案与协议不依赖服务端的操作系统或部署位置。退役条件另行决策。

## 第一阶段现状

本轮优先解决普通退后台/黑屏时已有任务执行、空闲后 Web 发起任务，以及内核必须由页面初始化的问题。执行内核抽为独立 JVM 模块 `agent-core`；Android 进程继续承载平台适配与会话控制器，不要求宿主 Root，不启动额外 TCP/LAN 服务。

```
手机 UI ──────────────┐
已鉴权 USB Web 桥 ────┼─> 进程级控制器 / Android 适配 ─> agent-core
JobScheduler 适配 ────┘               │
                              AgentTaskService
                          待命 / 活跃任务 / 主动关闭
```

`agent-core` 包含真实执行循环、工具调度、进展反馈、完成检查、模型请求预算与 30 秒重试、任务所有权、定时唤醒/周期计算，以及上下文预算、容量校准、压缩归档、模型账号选择、工具注册/发现/校验与契约装配。循环 Host 接口提供模型调用、上下文组装、工具执行、权限、事件、持久化和交付。保留原包名兼容现有调用；Android 不再维护这些实现的副本。

会话控制器暂保留 `CapriModel` 名称，但已不继承 AndroidViewModel，也不使用页面的 viewModelScope。`AgentRuntime` 持有进程唯一实例，页面、服务和 Web 共享同一份权威会话状态；Android 服务、原生工具、浏览器、Skill/MCP 具体实现与存储适配仍在 app 模块；这些依赖平台权限和宿主能力的实现通过端口向独立内核提供数据与执行。上下文和工具装配策略不再留在 Android 控制器中。

## 生命周期与后台入口

- 用户打开 Capri 时启动可见的内核前台宿主。无任务时显示“内核待命”，保留后台 Web 接入；不再在每轮任务结束后关闭宿主。
- 已运行宿主直接接纳后台 Web 新任务，不依赖再次从后台启动服务。任务仍按会话互斥，运行前必须确认宿主可用；服务启动失败不能当作执行成功。
- 活跃任务持有有超时的部分 CPU 唤醒锁，只保持必要 CPU 执行、不点亮屏幕；任务仍在执行时定期续期，任务完成、失败、取消或服务销毁时释放。空闲待命不持有 CPU 唤醒锁。
- 通知分别提供“停止任务”和“关闭内核”。前者取消 Agent 任务但保留待命；后者持久记录用户关闭意图，阻止新任务和后台分析调度，取消现有任务并给检查点收尾留出有界时间，再退出宿主。Web 健康轮询不撤销这个选择，重新打开 Capri 后才能启用。
- 宿主允许系统在进程回收后重新创建待命服务，但不自动重放中断的工具或会话。继续沿用检查点核验和显式“继续”。设备重启后默认不自动启动；设置中可显式启用“解锁后恢复内核待命”，BOOT_COMPLETED 接收器只恢复宿主与已有调度，不恢复执行中的工具。已有持久 JobScheduler 任务保留原调度语义。

前台服务与部分唤醒锁用于解决普通后台执行，不等于无限保活。强行停止、未首次解锁、深度省电、厂商限制、断电和真实断网的支持边界应分别验收；短时间熄屏通过不证明所有策略下长期在线。保持最多 30 秒网络恢复窗口，不引入永久等待。

## Web 冷启动与权限

电脑 USB 服务在读取手机桥接信息返回 not_ready 后，启动 `AgentTaskService`，不再拉起 MainActivity；宿主可自行初始化会话、工具适配与已鉴权 Unix socket。

ADB 启动入口只在 Debug 清单中导出，要求 `android.permission.DUMP`。Release 服务保持私有，没有 Debug provider 或 USB 管理命令。原有 Unix socket 对端 UID 检查、随机令牌、HTTP 同源限制、方法白名单、会话/历史版本校验和不重放未确认写操作的机制保持有效。主动关闭返回 kernel_stopped，Web 明确提示用户打开 Capri，不静默重新启动。

手机需要原生交互、权限确认或用户在场的工具仍可能要求返回前台；内核独立不扩大工具权限。

## 定时任务扩展点

`KernelTasks` 按归属键统一管理执行与取消；触发源不能改变权限或自动扩大执行范围。`KernelSchedule` 提供有界唤醒延时和完成时刻相对的周期计算，已接入现有可靠性调度。关闭内核会取消系统待调度入口并阻止再次派发，已有任务定义保留，重新打开 Capri 后再恢复调度。JobScheduler 负责系统唤醒，持久任务库继续负责 occurrence ID、领取、结果、暂停取消与未知效果，错过多个周期不突发补跑。

本轮不新增全能力无人值守 cron，也不改变已有后台分析任务的显式授权、只读范围和预算。以后新增定时触发器可复用内核执行接口与宿主，不需要重新依赖页面。

## 独立构建与检查

```
./gradlew -p agent-core test
python3 tools/verify.py --core-test ai.capri.core.KernelTest
```

独立入口不配置 Android 项目。模块只依赖 JVM、coroutines 和宿主提供的 org.json；不会引用 Activity、Compose、Android 服务或设备权限。集成检查继续覆盖执行/停止/预算/完成证据/纠正/恢复语义，不把模块能编译当作后台问题已解决。

端到端检查使用 `KernelHostDeviceTest` 与 `tools/kernel_host_smoke.py --serial <serial> --screen-off`：启动无页面宿主，真实 USB/Web 通道提交隔离会话任务，黑屏期间在 localhost TLS 模拟模型响应处等待，再确认一次推理完成、任务结束后 CPU 锁释放及宿主继续待命。不使用用户模型 Key，不改写用户聊天，不启用代理。该用例会重启应用且短暂熄屏，运行前要求所有用户任务空闲。

### 长时间黑屏与深度省电

“设置 → 内核与后台运行”统一展示宿主、CPU 锁、电池优化豁免、系统后台限制、省电/深度待机状态。页面恢复时重新读取系统状态；终端和 Agent 使用同一份系统策略诊断。

Android 的 Doze 会限制网络并忽略未豁免应用的部分唤醒锁，单独使用前台服务不能消除这项限制。页面提供主动点击的“允许长时间后台运行”，调用系统电池优化豁免确认；已允许时进入应用系统设置管理。应用启动不自动弹授权。豁免后活跃任务继续使用有超时、定期续期并在结束时释放的 CPU 锁；空闲不持锁。设备待机与省电广播触发宿主状态刷新，通知提示未豁免的深度待机限制。

新增可选的“解锁后恢复内核待命”，默认关闭；只响应正常解锁后的系统启动广播，并检查用户是否主动关闭内核。用户关闭内核优先于重启设置；启动失败只记录类别，不绕过系统限制或自动反复拉起。强行停止后必须重新打开，首次解锁前不启动，不自动重放中断效果。网络故障仍受原有最多 30 秒恢复窗口约束。

电池优化豁免改善的是 Android 标准 Doze 下网络与 CPU 的可用性；不等于所有厂商后台冻结、真实断网、强行停止或设备断电下无限运行。持久 JobScheduler 仍服从系统调度时机，不承诺深度待机下精确定时，也不增加永久唤醒、心跳轮询或精确闹钟。

## 第二阶段设计

- **先划清宿主接口**。执行循环已能独立构建，但 `CapriModel` 仍在 Android 模块持有会话控制逻辑，现有 Web 依赖 USB 桥。先沿现有会话和任务入口梳理可复用逻辑，定义会话、提交、取消、状态快照和事件订阅接口。Android UI 通过本地适配访问宿主；远程客户端通过版本化协议访问服务器。移动端进程拆分单独评估，依据故障隔离或生命周期需求决定。
- **先让服务器独立跑通最小闭环**。使用现有 `agent-core`，接入模型调用、持久存储和最小工具集。远程入口使用加密连接和鉴权，校验会话及工作区访问权限；模型凭据留在执行宿主。先用 Web 验证，再让 Android 接入同一服务。
- **明确数据和恢复归属**。每个会话由创建它的宿主管理。Android 通过设置切换宿主，两边的会话、工作区与任务各自独立。客户端重连按游标补事件，游标失效时取快照；提交使用请求标识去重，取消以宿主状态为准。重连与宿主重启分别处理，效果不明的工具调用进入恢复流程，避免自动重复执行。
- **区分宿主能力与外接设备能力**。服务器使用自己的工作区和工具，并可在同一任务中调用已配对的手机。独立宿主先用服务端工具跑通最小闭环，随后按下文接入 Android 设备能力。

首版完成条件是服务器在没有 Android 或 USB 的环境中独立完成一次任务；手机和 Web 能进入同一远程会话，其中一个客户端断线后重新看到同一任务进度，另一端可以发起取消，重复提交不会启动第二次执行。手机本地路径验证页面重建后能恢复观察，且本地数据与任务控制可继续使用。

## 重构边界与旧代码退役

按职责重构。先把 `CapriModel` 中由不同宿主共用的会话和任务逻辑抽出，再让 Android 本地路径通过新接口运行。用这条路径验证行为一致后，在 macOS 宿主接入对应适配器。

| --- | --- |
| **保留在内核** | 复用 `agent-core` 已有执行循环、上下文管理、模型配置策略、工具发现和任务所有权。把任务编排、取消、检查点、恢复语义和 Skill 快照语义收敛到可脱离 UI 的共用运行层。 |

## 客户端与内核协议

首次连接使用短时、一次性配对 Token。Android 支持扫码和粘贴，配置 Capri 服务地址后通过 HTTPS 兑换该客户端独立、可撤销的访问凭据。二维码携带服务地址和 Token。服务端在兑换成功时原子消耗 Token，防止重复使用。

宿主上的本地管理命令按操作系统账号权限鉴权。首次部署可用该命令生成首个网络客户端的配对 Token。已登录的 Web 管理页提供「添加客户端」，可生成短时一次性 Token，以二维码展示或复制给新客户端。

首版 Web 管理页显示已配对的客户端，支持逐台撤销访问。撤销沿用下文的客户端访问与任务规则。

已决策：所有已配对客户端拥有同等的完整操作权限，可以提交使用宿主管理员能力和手机 Root 能力的任务。实际执行仍以宿主管理员授权和手机接管授权的当前状态为准；客户端访问凭据可逐台撤销。

客户端撤销由云端宿主记录为内核可感知的状态变更。撤销后立即拒绝该客户端的新请求并关闭现有订阅。任务保留发起客户端的身份，内核可区分客户端断线与凭据撤销，并识别受影响的未完成任务。已接受的任务继续运行，其他仍获授权的客户端可以查看和取消。任务后续调用仍按宿主管理员授权和手机接管授权的当前状态执行。

首版支持公网访问。复用用户公网服务器上已运行的 FRPS，由 Mac mini 上的 FRPC 将请求转给 Capri 宿主。Android 和 Web 统一使用公网 HTTPS 服务地址，二维码使用同一地址。部署检查覆盖配对、API、SSE 续订和设备双向通道通过转发的行为，以及穿透重连后的状态恢复。客户端访问与设备控制继续由 Capri 分别鉴权。TLS 终止位置在部署时确认。

首版采用版本化 HTTPS JSON API 加可续订的 SSE 事件流。Android 和 Web 共用协议，服务端持有权威状态；本地模式可用进程内接口复用同一组领域命令和事件。手机作为被控设备时走单独的已鉴权双向连接，设备凭据和控制范围与聊天客户端身份分开。

| 协议部分 | 首版约定 |
| --- | --- |
| **资源和命令** | 明确定义会话、消息、任务、附件、设备和授权的 ID。提交和取消返回操作回执或任务 ID；客户端查状态确认结果。变更请求按调用者及资源范围去重；涉及并发编辑的操作校验版本。 |
| **状态和事件** | 提供带游标的快照，随后订阅消息、任务进度、工具结果、产物及授权变化。断线按游标继续；游标超出保留范围时重新取快照。任务状态、错误码和是否可重试有明确定义。 |
| **内容与权限** | 附件通过受控上传和下载端点传输，消息和事件引用附件 ID。每次读写按资源校验授权。设备协议只交付获准的工具调用及其回执。 |
| **演进** | 用 OpenAPI 和 JSON Schema 固定公开契约，按 API 版本处理破坏性变更，通过能力字段协商可选功能。两端用同一组契约用例验证重连、重复提交和旧客户端兼容。 |

## macOS 宿主与语言选择

首版用 Kotlin/JVM 复用现有内核，在 macOS 上交付无界面的 Capri 服务，并用相同宿主接口覆盖 Linux。宿主负责监听、鉴权、存储、凭据和进程管理。Android 设备端继续使用 Kotlin 和现有原生适配。

首版由用户在 Mac mini 上手动启动 Capri 和 FRPC。开机自动启动和无人登录时上线留待后续。未登录桌面时，任务先执行可在后台完成的步骤。遇到需要操作 Mac 图形界面的步骤时，任务暂停并报告等待桌面。用户登录且图形界面可用后，Capri 核对当前桌面状态及上一条操作的回执，确认可以继续时自动恢复。若期间云端 Capri 服务重启，则按服务重启规则等待用户手动继续。

云端 Capri 服务重启后，从持久化记录恢复会话、任务进度和检查点。被中断的任务进入等待手动继续状态。用户显式继续后，内核先核对中断前的工具回执和相关状态，再决定下一步。手机重连时的自动恢复仅适用于仍在等待设备的任务。

已决策：Capri 在宿主机上默认可使用运行身份已获得的全部系统权限，包括访问工作区之外的文件和执行命令。工作区用于组织任务和产物。macOS 首版提供独立的受管管理员执行入口。Capri 服务以普通用户身份常驻，需要管理员权限的操作通过该入口提交，由宿主侧校验授权并记录执行结果。管理员凭据由系统授权流程处理，模型和客户端只接收授权状态与操作回执。用户在宿主机完成一次管理员授权后，授权持久保存且无自动到期，跨任务、服务重启和宿主重启继续有效，直到用户在宿主机手动撤销。授权有效时，后续管理员操作仍通过受管入口校验并记录回执，无需逐次确认。

这里的目标是保住已有 Agent 行为，同时获得跨设备调度和可靠恢复。整套换语言会重新承担工具契约、上下文、取消与检查点的兼容成本。只有出现可测量的瓶颈或明确的部署约束，再评估把特定组件独立实现。Python 等工具运行时可通过现有工具边界接入。

## 云端 Capri 的设备接管

云端 Capri 指部署在用户自己的 macOS 或 Linux 上的独立宿主。它负责推理、会话、任务编排和工作区。已配对的手机是服务端 Capri 可调用的设备。Android App 可同时承载聊天界面和设备执行服务，二者有各自的连接与生命周期。从 Web 发起的同一任务可以先处理服务器文件，再操作手机，最后回到服务器整理结果。

### 发现设备与能力

- **登记设备身份。** 手机执行服务主动建立经鉴权的加密连接，经用户在手机上确认配对后，服务端登记稳定设备 ID、所有者、别名、平台与系统版本。设备 ID 跨重连保持稳定；用户可指定默认手机，让「我的手机」解析到该 ID。有多台候选且无默认设备时，先确认目标。
- **发现能力。** 内核先发现设备，再按需发现该设备支持的动作。平台适配器定义可实现的能力，具体设备报告当前版本、连接状态、实际验证过的能力和所需授权。发现结果区分设备离线、平台不支持、依赖缺失、尚未授权和可调用。离线保留设备身份，历史能力只作为上次观测。
- **按平台扩展。** 首个适配器为 Android。通用协议只约定设备身份、平台、能力及版本、授权范围、调用回执、取消和状态变化。Android 的 App、界面、网络与 Root 语义留在 Android 适配器。以后 Windows、macOS、路由器可分别以适配器接入，声明自己支持的能力；macOS 作为服务器宿主和作为被控设备是两个独立角色。

### 授权与实际接管

- **分开配对、控制授权与系统权限。** 客户端配对建立访问服务的身份。用户在手机上开启接管时，控制授权默认覆盖手机适配器已支持且系统已授予的全部能力，包括普通界面操作、敏感数据读取，以及可用的 Root 检查、命令执行与托管服务。手机端签发、持久保存并执行接管授权，绑定已配对的服务端身份和本机设备。开启后持续有效，直到用户在手机上手动关闭。同一服务端断线重连并重新通过身份校验后，自动恢复接管资格。恢复资格与恢复任务执行分别处理，效果未知的旧调用仍按回执和设备状态核对。系统尚未授予的权限仍由 Android 或 Root 管理器确认。授权范围内的连续操作无需逐步确认，用户可在手机端随时停止接管。
- **设备端执行。** 服务器给每次调用指定设备、任务、能力、请求 ID 和截止时间。手机校验授权和参数，再把调用交给本地执行器。界面接管通过反复观察当前 App 和界面、点击或输入、再观察验证形成闭环。手机界面锁定、系统要求用户确认或设备离线时，返回可识别状态供内核暂停对应步骤。界面观察与交互能力需通过 Android 适配器补齐。
- **手机可以结束接管。** 本地停止立即撤销控制授权，拒绝排队和后续调用，并取消能中断的工作及回收托管资源。回执区分已接收、执行中、已完成和结果未知。按请求 ID 去重；断线后先核对回执或设备实际状态，避免重复点击、执行命令或启动服务。已产生的设备效果以实际状态为准。

### Android、Root 与现有工具

远程接管空闲时，手机端仅维持连接和必要的低频心跳。断线后退避重连，网络变化时触发重连；空闲时释放 CPU 唤醒锁、停止截图与界面轮询，按任务启停 Frida 等执行资源。仅在任务需要图形界面且设备在线时尝试唤醒屏幕，确认无密码锁屏已解除、目标 App 已到前台后再执行。图形操作结束、取消或超时后释放屏幕与执行资源，让系统恢复正常熄屏。低待机耗电是首版验收条件。用户会随身携带手机，按需唤醒和空闲耗电须一起验收。在同一手机、相近条件下对比接管关闭与空闲在线时的熄屏耗电，并分别在 Wi‑Fi 和移动数据下检查能否按需唤醒及唤醒延迟。以实测基线评估额外耗电，调整心跳与重连策略。

实现 Android 界面操控前，先调研开源手机 Agent，评估可复用的界面观察、元素定位、手势输入和结果验证能力。用「打开指定 App 并自主完成一条多步操作路径」检验候选方案，同时检查能否接入 Capri 的手机执行服务，供云端内核调用。

手机暂时离线时，云端任务暂停依赖该设备的步骤，并报告等待设备。原设备重连后，内核重新检查接管授权、能力和当前设备状态，核对上一条调用的回执；确认可继续时自动恢复。无法确认上一条操作效果时保持暂停，等待核实或用户处理。

本地与云端通过手机端同一个设备控制锁互斥。同一时刻只允许一个任务持有控制权，后来者收到 `device_busy`。任务完成或取消并释放控制权后，其他任务可以重新申请。

已决策：已 Root 的 Android 手机开启接管后，目标是向云端 Capri 提供该设备实际可用的完整能力范围，覆盖现有原生工具、UI 操作、设备网络、手机终端、宿主 Root 命令、托管 Root 服务及具备依赖时的 Frida/REA。专用工具提供能力发现和结构化结果，受管 `root_exec` 为尚无专用工具的 Android 宿主操作提供通用执行入口。设备实际能力由 `su` 授权、系统策略和运行时依赖决定；服务端能查询缺失条件。首批验证用例用于验证接管链路，完整能力覆盖需按现有工具契约逐项核对。

- **复用工具契约和执行器。** 在现有工具发现与分发之间增加设备路由。保留 Android 原生工具、网络工具和终端的契约，按调用绑定的设备 ID 调到手机执行器，继续使用原有参数校验、权限检查、会话隔离与取消机制。手机网络检测使用手机网络；手机终端和服务器终端各有自己的环境与工作区。
- **让模型理解 Root 的实际状态。** Android 适配器区分设备的 Root 证据、Capri 应用是否获得 `su` 授权、本次远程接管是否允许使用 Root，以及托管运行时的依赖是否就绪。复用 `root_status`、`root_request` 和 `root_inspect`，在具有单独执行授权时接入 `root_exec`、`root_service`。保留执行前身份验证、作用域和生命周期限制。PRoot 终端仍使用应用权限，Android 宿主 Root 通过受管入口执行。
- **首版在服务端运行静态分析，在手机上运行动态分析。** APK 和原生二进制的静态分析后端部署在 macOS 宿主，按授权读取传入的样本或产物。现有安装脚本含 Linux ARM64 依赖，迁移时逐项验证后端兼容性。动态分析复用手机上的 REA 运行时、Frida 客户端和托管 Frida 服务，沿用设备侧 Root 授权、会话作用域和清理机制。云端 Capri 按设备 ID 调用并汇总结果。接口区分目标设备与执行位置，便于后续迁移动态分析控制端。

### Skill 与资源复用

- **服务端加载 Skill 快照。** 沿用现有 Skill ID、版本、快照与资源读取。用户可选择共享现有手机 Skill 的指定版本及资源，服务端加载该快照用于推理。同一 Skill 可以连续调用服务器工具与手机工具，Skill 的内容和来源不改变设备授权。
- **按执行环境交付资源。** 依赖 Android、手机网络或 Root 的脚本交给绑定的 Android 执行器，按需传入指定版本的资源。分析或处理类脚本可在满足依赖的服务端运行。传输文件时显式选择目标设备和受限工作区，校验版本或摘要；服务端路径与手机路径分别解析。设备或依赖不满足时，返回具体缺失条件供内核处理。
- **Weapon 按步骤选择执行位置。** 服务端管理目录、版本和流程。依赖目标手机权限、网络位置或硬件的步骤在手机执行，适合迁移的静态分析和结果处理可在 Mac 上执行。首版优先兼容现有 Weapon 的脚本、行为和执行环境，通过适配层接入，迁移所必需的修改控制在最小范围。后续逐个评估和优化执行位置、依赖与清理动作。

### 首批验证范围

首版由用户在 Mac mini 和已 Root 的主力安卓机上手动验收。从另一台终端打开云端 Capri，发出指令，确认 Capri 能操作已接入的设备并发挥预设能力。下列场景供开发联调和用户试用时参考。

首个可用版本以完整接入为交付门槛，覆盖现有原生工具、手机终端、Root、Frida/REA 和依赖这些能力的 Skill（含 Weapon）。下列链路可在开发期间先验证，交付时另按现有能力清单核对覆盖与兼容。

1. 在 macOS 或 Linux 的独立宿主上，从 Web 说「用我的手机」能解析到已配对 Android 设备，并看到手机在线状态、授权范围和实际验证的 Root 能力。
2. 在同一任务内，使用已授权 Skill 连续操作手机界面、调用现有原生工具和一次受管 Root 检查，再把结果写入服务端工作区。具备单独 Root 执行授权时，验证受管 Root 命令入口及撤销行为。
3. 验证手机端停止接管、锁屏、断线和权限变化能被内核识别；重连后已有调用可查回执，结果未知的操作不会自动重放。
