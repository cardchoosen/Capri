# 执行循环与任务控制：首版实现

日期：2026-10-30。对应[优化待办](AGENT_OPTIMIZATION_TODO.zh-CN.md)第一大项的六个子项；后续大项尚未启动。

## 阶段与恢复

`agent/TurnState.kt` 在原有原子任务检查点中保存执行控制状态。阶段包括准备、推理、工具执行、恢复、交付、等待用户，以及完成、未完成、预算耗尽、取消、失败。手机与 Web 显示同一份阶段和请求计数，阶段日志不记录提示词或工具输出。

任务状态按会话与历史修订隔离。用户消息新增可选 `control` 元数据，区分执行中补充和澄清回答；旧历史无此字段仍可读取。原始用户目标继续保存在 TaskState，不因补充要求或回答问题而覆盖。

## 执行中补充要求

- 手机执行中显示独立停止按钮和发送补充要求按钮；Web 保留停止入口，并允许在忙碌时发送。输入框会解释补充在安全边界接入。
- 接收后先持久化用户消息及附件，再确认接收。控制器用消息 ID 记录已接入内容，恢复时不会重复注入。
- 一次最多待接入 8 条补充，单条最多 32,000 字符，待接入正文合计最多 128,000 字符；Web 还沿用单次消息的 UTF-8 字节限制。
- 如果模型推理期间收到补充，旧响应中的操作不派发；重新按新输入推理。
- 如果工具批次执行期间收到补充，已启动的操作继续完成或由用户停止；尚未派发的操作记录为 `not_executed`，随后重新判断。已产生的副作用不自动撤销。
- 若人物收尾期间收到补充，旧答复不发布，保存输入并返回执行循环。真正完成交付后才拒绝继续向已结束任务排队。
- 启动时捕获本轮原始消息，避免刚开始就收到补充时误把补充当成新任务目标。新任务不继承旧任务的证据与待接入计数。

补充输入不会自动取消已经开始的系统调用、终端命令或远端操作。需要立即取消时仍使用停止入口；停止也不能保证撤回已经发生的外部副作用。

## 结构化澄清

新增第一方工具 `ask_user(question, options?)`，用于缺少必要信息而无法继续的情况。问题非空且不超过 2,000 字符，可选 2–5 个选项，每项最多 200 字符。

问题与工具结果一并保存，后续同批操作不派发，任务进入等待状态，不进入完成交付。问题保留在聊天记录；选项可填入手机或 Web 输入框，由用户发送。回答从已保存任务继续，原目标、工具结果与计划保留。文件和图片也可随补充或回答接入。

用户输入是本轮要求，不构成无限权限；澄清工具不能替代既有权限检查。纯“继续”也不会由框架猜出答案，模型仍须判断信息是否充足。

## 请求预算

ModelRequests 按执行、上下文摘要、人物收尾分别统计客户端请求尝试，网络重试仍计入对应阶段，另记重试次数。模型收到最大值、已用、剩余与收尾预留的简短反馈。

执行和摘要不能使用预留的最后一次人物收尾请求；重试也遵守预留。预算耗尽进入明确状态并保留检查点，不把耗尽当成任务完成。当前仍是每轮预算，接续会建立新一轮预算；不是跨轮总费用或 token 的精确配额。

## 完成判断

`task_state` 增加 `finish` 操作，记录 `completed`、`partial` 或 `blocked`、事实摘要与实际工具调用 ID。执行性工具调用、任务计划，以及保守识别的明确行动请求，在收尾前需要核对该评估。

- 计划记录、工具发现结果和虚构调用 ID 不能充当工作证据。
- 失败、部分失败、运行中、未派发或崩溃后结果未知的记录不能充当成功证据。
- 存在未完成计划时，不能直接评估为完成；部分完成或阻塞可如实交付，但检查点继续保留。
- 新工作结果或用户补充会使已有交付评估失效，需要重新核对。
- 仅讨论方案、普通问答和创作不要求凭空执行工具。自然语言行动匹配只覆盖保守的明确表达，不是通用意图识别器。

这些检查约束的是证据来源与已知失败信号，不能自动证明任意用户目标已经满足，也不能识别所有错误宣称。模型仍须核实具体产物、内容和验证结果；`status=ok` 本身不代表目标完成。首版未加入独立评审模型或通用语义验收器。

## 停滞处理

ProgressGuard 对等价 JSON 参数及结果生成摘要，区分重复失败、无变化终端读取和重复操作。第三次相同证据给出针对性调整提示；最近 12 次记录中同一模式达到六次时，本轮按未完成退出并保留结果。

该机制不缓存、重放或撤销工具操作，也不会替模型发明新的执行权限。摘要保存在检查点，接续可识别原有重复；收到新的用户补充会重置进展窗口。判定不等同语义上的“毫无进展”，仍需结合实际任务检验误判和收益。
