# Capri Agent 优化待办

建立日期：2026-10-30。

本清单记录与用户讨论确定的十个优化方向，主要参考 Hermes Agent。每次只讨论一个大项：先核对 Capri 当前实现和具体问题，再确定范围、方案与验收方式，最后实施。未讨论的大项保持待办，不据此自动启动全部重构。

子项中的已有机制也保留为待办，表示仍需审查、补齐或验证，不表示从零实现。复选框只有在约定范围和验收完成后才勾选。Skills、人格等交叉内容应与对应专项衔接，避免重复实现。

## 1. 执行循环与任务控制

- [x] **1.1 明确执行阶段**：审查已有 AgentLoop，将准备、推理、执行、恢复、交付的状态与边界明确下来，减少 CapriModel 的交叉职责。
- [x] **1.2 执行中插话与转向**：用户补充约束时，在安全边界接入当前任务，保留已发生的操作与结果。
- [x] **1.3 结构化澄清**：必要信息缺失时进入可恢复的等待状态，答案回到原任务。
- [x] **1.4 可解释的请求预算**：区分正常推理、重试、摘要和收尾的消耗，向模型提供剩余预算。
- [x] **1.5 完成与未完成的区分**：把交付条件与实际产物、验证证据关联，不只依赖模型自述或计划状态。
- [x] **1.6 停滞后的策略调整**：区分无变化轮询、重复失败、参数修正与正常重试，审查已有 ProgressGuard 的提醒效果。

验收重点：插话后约束保留、取消与恢复边界、必要澄清可接续、不会因预算或提醒错误标记完成。

2026-10-30：六个子项完成首版实现与聚焦验收。实现、验证范围与限制见[执行循环与任务控制](AGENT_TURN_CONTROL.zh-CN.md)。自然语言识别和工具证据检查不构成通用目标证明，真实任务效果仍需后续对照。

## 2. 响应速度与模型调用

- [ ] **2.1 流式输出（本轮暂缓）**：已有执行过程展示；真正的文字增量与其不同，暂不作为必改项。后续需要时再评估文本增量、工具调用生成状态和最终回复流式传输，保持中断及协议兼容。
- [ ] **2.2 稳定提示词前缀（待进一步说明，暂不单独推进）**：固定规则与易变状态分层，减少时间、环境和目录变化对公共前缀的影响。
- [ ] **2.3 供应商提示词缓存（用户决定本轮不做）**：不新增供应商缓存适配或开关；已有供应商返回的统计可以保留。
- [ ] **2.4 辅助模型分工（同意，先设计受控验证）**：用固定输入比较事实／约束保留、耗时和费用，先考虑摘要等可核验环节；不直接全面替换。评估摘要、网页提取、视觉等独立配置，明确能力、费用和数据目的地。
- [x] **2.5 人物收尾成本控制（同意）**：保留 Capri 人格，比较必须二次生成与可一次完成的场景。
- [x] **2.6 分阶段延迟统计（同意，先推进）**：复用已有记录，核对哪些阶段仍无法归因，再补齐排队、首段输出、完整响应、工具等待和收尾耗时，避免嵌套耗时重复相加。

验收重点：固定模型与任务的总耗时、请求次数、费用和答复质量。已有执行过程展示与真正的模型文字流式输出分开评价，不把前者误写成后者。供应商缓存不在本轮实施范围。

2026-10-30 初步核对：现有日志已经记录模型请求、响应头／正文／解析、工具、重试与人物收尾。两个历史单例中，收尾分别占总耗时约 16.2% 和 45.7%；不是当前性能基准。模型请求被包含在收尾阶段内，不能相加；排队、上下文准备和请求用途的归因仍需检查。材料：`work/agent-latency/2026-10-30/initial-baseline.json`。

2026-10-30 实现更新：用途标签、准备／排队计时和不重复归因已接入；明确纯 JSON 的直接交付及管理记录缩减通过受控真机验收。辅助摘要仅提供离线夹具，当前只有 DeepSeek 接入，未启用自动分工或进行真实模型对照。详见[响应耗时与人物收尾](AGENT_LATENCY.zh-CN.md)。

## 3. 上下文管理

- [x] **3.1 可替换的上下文策略**：将选择与摘要策略抽成接口，支持对照不同方案。
- [x] **3.2 用户约束的专门保护**：保护原始目标、后续纠正、禁止事项与验收条件，检验压缩后的保留情况。
- [x] **3.3 完整交互组压缩**：调用与结果成组处理，保持恢复依据和供应商历史格式合法。
- [x] **3.4 按内容类型缩减结果**：在已有归档基础上分别处理搜索结果、日志、目录树和网页正文。
- [x] **3.5 微压缩或分批摘要**：实验集中停顿、额外调用、缓存损失和细节保留的取舍，不默认启用。
- [x] **3.6 压缩前知识保存**：识别值得持久化的信息，衔接记忆与 Skill，避免临时结论变成长期事实。

验收重点：约束与证据保留、摘要失真、恢复正确性、实际上下文成本和压缩延迟。

2026-10-30：六子项完成首版实现与聚焦验证，见[上下文管理](AGENT_CONTEXT.zh-CN.md)。默认压力策略；微压缩仅显式注入实验。压缩前保存任务内交接及未验证知识候选，不自动写长期记忆或 Skill。真实 DeepSeek 摘要质量、总延迟、费用和缓存影响尚未对照，复选框表示本轮实现范围完成，不表示这些实验已得出最优结论。

## 4. 工具发现与能力感知

- [x] **4.1 统一工具注册表**：收敛定义、校验、执行、目录、显示名称和可用条件，保持现有标识兼容。
- [x] **4.2 明确能力可用状态**：区分已配置、立即可用、需授权、需准备、暂不可用及原因。
- [x] **4.3 高频核心工具直接提供**：重评延迟加载名单，尤其是 Android、浏览器等手机高频能力。
- [x] **4.4 更好的工具检索**：评估多查询、词形、同义表达和服务领域提示，避免把未命中解释为能力不存在。
- [x] **4.5 延迟工具的统一调用入口**：实验桥接调用是否减少往返，底层仍逐项执行权限、参数和范围检查。
- [x] **4.6 工具定义工作集管理**：限制累积加载，统计被提供与实际使用的关系，并处理工具撤回。

验收重点：能力发现成功率、错误选工具比例、无效调用、上下文成本和整轮耗时。

2026-10-30：六子项已实施，详见[工具发现与能力感知](AGENT_DISCOVERY.zh-CN.md)。Android/browser 直接提供；共享契约快照、MCP 配置状态、中英文多查询、受控 tool_invoke、LRU 与数值统计已接入。桥接沿用原有授权与恢复语义。真实模型的选工具质量、端到端耗时和费用仍需固定任务对照，不把受控夹具当作普遍提速证明。Skills 库优化继续由独立专项负责。

## 5. 程序化调用与运行效率

- [ ] **5.1 脚本组合调用工具**：评估受控 RPC，使搜索、筛选、读取、汇总等确定流程减少模型决策次数。
- [ ] **5.2 中间数据留在执行侧**：程序先过滤批量结果，只将必要输出、异常和证据引用交回模型。
- [ ] **5.3 会话级持久计算内核**：实验导入、变量与数据复用，明确超时、重置和环境变化后的失效行为。
- [ ] **5.4 可控批处理**：扩展适合批量查询的操作，保留每项结果和部分失败语义。
- [ ] **5.5 按资源限制并发**：按网络、磁盘、CPU、内存任务设置并发，保留顺序屏障。
- [ ] **5.6 统一脚本资源预算**：限制时间、输出、工具调用数与递归，沿用正常权限和取消机制。

验收重点：减少模型往返的实际收益、资源峰值、部分失败、取消和会话隔离。

## 6. Coding 能力

- [ ] **6.1 写入后的轻量语法检查**：统一高频文件格式的直接错误反馈。
- [ ] **6.2 LSP 语义诊断**：从少量高频语言试点，评估手机内存、启动时间和项目执行边界。
- [ ] **6.3 只报告新增诊断**：比较修改前后，区分历史问题与本次引入的问题。
- [ ] **6.4 慢诊断异步交付**：冷启动诊断不阻塞每次写入，结果仍能回到对应任务与文件版本。
- [ ] **6.5 修改前的文件快照**：与任务检查点分开，设计可核对的回滚并保护用户已有修改。
- [ ] **6.6 文件、目录和 diff 引用**：在附件之外增加精确项目引用，减少定位错误与重复探索。

验收重点：真实修改任务的正确率、修复轮数、诊断新增与过期处理、回滚和资源成本；复用现有项目规则与精确补丁能力。

## 7. 终端与长任务生命周期

- [ ] **7.1 统一进程登记**：收敛归属、命令、状态、输出位置和取消方式。
- [ ] **7.2 完成事件代替频繁轮询**：长构建、下载等完成后唤醒任务，减少无变化查询。
- [ ] **7.3 持久化完成回执**：进程结果独立保存，应用重启后可核对，不凭 PID 或句柄错误认领。
- [ ] **7.4 增量输出与背压**：统一持续终端、短任务、安装和构建输出的偏移、分页与上限。
- [ ] **7.5 环境后端抽象**：评估本地与 SSH 等远端后端，保持统一任务和结果语义。
- [ ] **7.6 环境事实复用与失效**：完善安装环境档案的变更失效规则，减少重复检测与安装。

验收重点：轮询次数、长任务完成交付、重启后归属与结果恢复、输出遗漏和取消传播。

## 8. 记忆、Skills 与经验复用

- [ ] **8.1 区分不同知识类型**：明确用户事实、项目约定、环境事实、任务状态和操作经验各自归属。
- [ ] **8.2 有容量上限的精选记忆**：审查容量与整理策略，保持长期注入简短、相关、可解释。
- [ ] **8.3 历史检索后再回答**：加强已有检索的触发、作用域和证据引用。
- [ ] **8.4 记忆快照与实时变化分离**：实验稳定公共提示词与本轮变化增量的组合。
- [ ] **8.5 从成功任务提炼 Skill**：衔接独立专项，沉淀触发条件、步骤、验证和失败分支，避免一次性流水账。
- [ ] **8.6 Skill 使用后的修订闭环**：记录失败、过期依赖和用户纠正，更新可比较、可回退且保留来源。

验收重点：召回相关性、过期与冲突事实处理、错误记忆传播、Skill 实际复用效果；新写和修改的第一方 Skill 遵守英文契约规则。

## 9. 多 Agent 与复杂任务分工

- [ ] **9.1 子任务上下文隔离**：只传必要目标、约束与证据，避免整段历史复制。
- [ ] **9.2 子任务能力限制**：按职责配置工具和权限，不默认继承全部能力。
- [ ] **9.3 父子预算统筹**：限制总费用、并发、请求数和手机资源，而非只限制单个子 Agent。
- [ ] **9.4 并行修改隔离**：设计独立工作区或 worktree、修改归属和合并方式。
- [ ] **9.5 结构化结果返回**：返回产物、证据、未决问题与状态，控制主上下文膨胀。
- [ ] **9.6 选择性委派**：用独立调查、审查、批量任务验证收益，同时衡量协调与汇总成本。

验收重点：与单 Agent 的成功率、总耗时和费用对照，跨任务隔离、冲突处理及取消行为。不把默认多开 Agent 当作提速保证。

## 10. 可靠性、长期运行与评估

- [ ] **10.1 可追踪的会话分支**：记录压缩、恢复和历史编辑的父子关系与状态来源。
- [ ] **10.2 模型与辅助调用的独立容错**：审查现有重试，评估备用路线，明确能力、费用和数据目的地变化。
- [ ] **10.3 持久目标与后台续作**：区分长任务、等待外部结果和周期任务，结合 Android 生命周期恢复。
- [ ] **10.4 定时及事件触发任务**：明确目标、执行身份、结果保存、失败处理、暂停和取消。
- [ ] **10.5 统一事件与扩展接口**：让手机、Web、日志和插件消费同一套任务事件，减少行为分叉。
- [ ] **10.6 固定任务集与轨迹回放**：固定模型、环境和任务，衡量成功率、耗时、费用、重复操作、恢复和约束保留。

验收重点：恢复与去重、长期状态一致性、任务归属以及可重复的效果对照。固定任务基线可作为前面各项的验收支撑提前建立，不改变逐项讨论的顺序。

## 衡量与决策约定

- 不把工具调用减少、英文契约、并发或 token 下降直接等同于质量和速度提升。
- 默认复用已有构建、环境证据和通过记录，只运行与变化相关的验证。
- 流式、缓存、微压缩、辅助模型、持久内核、LSP、多 Agent 都要明确成本和适用条件，再决定是否启用。
- 每个大项讨论后，在对应章节记录确定范围、取舍、实施状态、验收记录和剩余问题。
