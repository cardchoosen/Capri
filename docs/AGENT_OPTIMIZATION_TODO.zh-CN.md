# Capri Agent 优化待办

建立日期：2026-10-30。

本清单记录与用户讨论确定的十个优化方向，主要参考 Hermes Agent。每次只讨论一个大项：先核对 Capri 当前实现和具体问题，再确定范围、方案与验收方式，最后实施。未讨论的大项保持待办，不据此自动启动全部重构。

子项中的已有机制也保留为待办，表示仍需审查、补齐或验证，不表示从零实现。复选框只有在约定范围和验收完成后才勾选。Skills、人格等交叉内容应与对应专项衔接，避免重复实现。

## 终极目标：个人核心工作助手

- [ ] 将 Capri 打造成个人核心工作助手。从任意已授权终端随时进入个人工作室，查看所有已连接设备的实时状态和可用能力，在授权范围内直接操作设备或交由 Capri 执行。能够打开设备上的应用、文件和工作环境，并在同一任务中调用多台设备协作，让远程工作像坐在家里一样。

当前设备包括若干手机、一台较高配置的 Windows 主机和一台 Mac mini。内核独立专项先以 Mac mini 承载 Capri 内核、接入已 Root 的主力安卓机为起点，再逐步覆盖其他手机和 Windows 主机，按设备提供相应的操作能力。见[内核独立专项](KERNEL_INDEPENDENCE.zh-CN.md)。

## 1. 执行循环与任务控制

- [x] **1.1 明确执行阶段**：审查已有 AgentLoop，将准备、推理、执行、恢复、交付的状态与边界明确下来，减少 CapriModel 的交叉职责。
- [x] **1.2 执行中插话与转向**：用户补充约束时，在安全边界接入当前任务，保留已发生的操作与结果。
- [x] **1.3 结构化澄清**：必要信息缺失时进入可恢复的等待状态，答案回到原任务。
- [x] **1.4 可解释的请求预算**：区分正常推理、重试、摘要和收尾的消耗，向模型提供剩余预算。
- [x] **1.5 完成与未完成的区分**：把交付条件与实际产物、验证证据关联，不只依赖模型自述或计划状态。
- [x] **1.6 停滞后的策略调整**：区分无变化轮询、重复失败、参数修正与正常重试，审查已有 ProgressGuard 的提醒效果。

验收重点：插话后约束保留、取消与恢复边界、必要澄清可接续、不会因预算或提醒错误标记完成。

2026-10-30：六个子项完成首版实现与聚焦验收。实现、验证范围与限制见[执行循环与任务控制](AGENT_TURN_CONTROL.zh-CN.md)。自然语言识别和工具证据检查不构成通用目标证明，真实任务效果仍需后续对照。

## 2. 响应速度与模型调用

- [ ] **2.1 流式输出（本轮暂缓）**：已有执行过程展示；真正的文字增量与其不同，暂不作为必改项。后续需要时再评估文本增量、工具调用生成状态和最终回复流式传输，保持中断及协议兼容。
- [ ] **2.2 稳定提示词前缀（待进一步说明，暂不单独推进）**：固定规则与易变状态分层，减少时间、环境和目录变化对公共前缀的影响。
- [ ] **2.3 供应商提示词缓存（用户决定本轮不做）**：不新增供应商缓存适配或开关；已有供应商返回的统计可以保留。
- [ ] **2.4 辅助模型分工（同意，先设计受控验证）**：用固定输入比较事实／约束保留、耗时和费用，先考虑摘要等可核验环节；不直接全面替换。评估摘要、网页提取、视觉等独立配置，明确能力、费用和数据目的地。
- [x] **2.5 人物收尾成本控制（同意）**：保留 Capri 人格，比较必须二次生成与可一次完成的场景。
- [x] **2.6 分阶段延迟统计（同意，先推进）**：复用已有记录，核对哪些阶段仍无法归因，再补齐排队、首段输出、完整响应、工具等待和收尾耗时，避免嵌套耗时重复相加。

验收重点：固定模型与任务的总耗时、请求次数、费用和答复质量。已有执行过程展示与真正的模型文字流式输出分开评价，不把前者误写成后者。供应商缓存不在本轮实施范围。

2026-10-30 初步核对：现有日志已经记录模型请求、响应头／正文／解析、工具、重试与人物收尾。两个历史单例中，收尾分别占总耗时约 16.2% 和 45.7%；不是当前性能基准。模型请求被包含在收尾阶段内，不能相加；排队、上下文准备和请求用途的归因仍需检查。材料：`work/agent-latency/2026-10-30/initial-baseline.json`。

2026-10-30 实现更新：用途标签、准备／排队计时和不重复归因已接入；明确纯 JSON 的直接交付及管理记录缩减通过受控真机验收。辅助摘要仅提供离线夹具，当前只有 DeepSeek 接入，未启用自动分工或进行真实模型对照。详见[响应耗时与人物收尾](AGENT_LATENCY.zh-CN.md)。

- [x] **10.5 统一事件与扩展接口**：让手机、Web、日志和插件消费同一套任务事件，减少行为分叉。
- [x] **10.6 固定任务集与轨迹回放**：固定模型、环境和任务，衡量成功率、耗时、费用、重复操作、恢复和约束保留。

验收重点：恢复与去重、长期状态一致性、任务归属以及可重复的效果对照。固定任务基线可作为前面各项的验收支撑提前建立，不改变逐项讨论的顺序。

2026-11-02：六子项的受限首版已实施，见[可靠性、长期运行与评估](AGENT_RELIABILITY.zh-CN.md)。统一元数据事件与检查点来源链、按用途模型预算／失败计数、持久目标、Android JobScheduler、显式授权只读文件分析、定时与来源事件触发、暂停取消／崩溃不重放和固定轨迹回放已接入。当前模型路线不自动切换；任意全能力 Agent 后台续作、外部网页监控与第三方事件注入未实现。主机验证不替代 Android 调度、保活、真实模型和费用验收。

### Capri 瘦身专项

**目标与边界**：优先通过删除已确认无用的实现、整合重复逻辑和简化模块边界实现明显瘦身，不删减功能，不通过压缩排版、牺牲可读性或删除有效回归测试凑数字。尚未核实的冗余先列候选，不直接删除。

- [ ] **建立基线与清理清单**：记录有效源码量、重复逻辑、依赖、内置资源和 APK 体积；结合调用链、动态工具注册、反射、构建变体和现有验证记录确认哪些实现确实无用。区分代码精简、安装包减小、上下文减少及运行性能收益。
- [ ] **清理遗留与无效内容**：检查旧架构、废弃入口、重复适配、失效配置及过时资源；保留仍承担历史数据迁移、兼容与恢复职责的代码，明确其退出条件后再移除。
- [ ] **合并重复实现**：审查手机/Web 共用业务、模型配置、工具契约与参数校验、文件与附件处理、错误处理及持久化逻辑，尽量保留单一事实来源，避免两端各维护一份规则。
- [ ] **简化核心模块**：整理 Agent 执行、任务生命周期、上下文、Skill/MCP 与运行环境的职责边界，合并无实际价值的包装层；按业务职责拆分过大的模块，不引入仅为减少行数的通用框架。
- [ ] **审查依赖与产物**：检查重复或未使用的库、重复打包资源、测试夹具和生成物；验证依赖移除及裁剪对运行时加载、离线能力、第三方许可和 Debug/Release 构建的影响。
- [ ] **分批验证与量化验收**：每批记录修改前后指标、等价行为证据和回退方式，完成相关核心路径检查后再进入下一批。先根据基线提出可实现的缩减目标，再确认各批范围。

**功能不变的验收重点**：手机与 Web 的聊天、历史编辑、模型选择、附件与预览；Agent 工具执行、停止、后台服务、预算与检查点恢复；Skills/MCP、权限与会话隔离；已有聊天、配置、工作区和个人产物的兼容与保留。用户可见行为或已有工具契约确需变化时，单独讨论，不作为“瘦身”直接合入。

**专项衔接**：复用 Agent 优化、Skill 优化、角色设计及动态分析专项的实现和验证证据，避免平行改写同一模块。只建立本待办，不自动启动仓库级重构。

### Capri 内核独立专项

**目标**：同一套内核既可由 Android 宿主本地运行，也可部署在服务器上供 Android 与 Web 客户端连接。由所选宿主管理任务和会话，客户端独立于任务生命周期。

第一阶段已交付的范围：

- [x] **复现并定位后台全链路问题**：分别核对黑屏/锁屏、普通退后台、页面销毁、空闲后 Web 新建任务、任务运行中切应用等场景，检查进程、网络、服务启动、Web 连接和工具执行的中断点。已有前台服务、进程级 owner 和独立任务作用域是可复用基础，不代表这些场景已全部解决。
- [x] **划清内核与平台适配边界**：梳理 Agent 循环、模型请求、上下文、会话存储、工具/Skill/MCP、任务调度及事件流；将 Android 生命周期、权限、通知和设备能力放入明确的平台适配层。评估独立构建与测试的模块方案，以及运行时是否需要独立进程，方案确认后实施。
- [x] **建立独立运行宿主**：由运行宿主管理内核启动、存续、退出和状态恢复，不依赖 Activity 或打开页面初始化。明确活跃任务与空闲待命的生命周期，让退后台后从 Web 发起的新任务也能进入运行路径；评估电量、通知和资源占用，避免只保障“已经开始的任务”。
- [x] **统一手机与 Web 的内核接口**：提供会话、模型、文件、任务控制与状态订阅接口，保持同一份权威状态，支持客户端断开、重连和页面重建。连接恢复与任务执行分开处理，保留鉴权、会话隔离、操作回执和去重，避免重连时重复执行工具。
- [x] **完善黑屏与异常恢复**：明确执行、网络和必要资源的持有与释放方式；分别约定锁屏、系统回收、设备重启及用户强行停止后的支持范围与恢复动作。复用检查点并核验未知副作用；保留已约定的最多 30 秒网络重试，不引入永久等待或无条件重放。
- [x] **提供定时任务扩展点**：衔接已有持久任务与受限调度能力，统一任务入口、触发器、持久状态和运行回执；规划单次/周期任务、时区、错过执行时刻、重启恢复、并发互斥、暂停取消及去重语义。无人值守工具权限、模型费用预算和需要用户在场的步骤明确配置，不把调度成功当作任务完成。
- [x] **支持内核独立维护**：形成清晰的模块依赖、稳定接口和版本兼容约定，建立不依赖手机页面的核心测试、平台适配测试与日志诊断入口。保留现有聊天、模型配置、工作区、Skill 和检查点的迁移与回退路径。

- [ ] 定义 Android 与 Web 共用的版本化客户端协议，覆盖资源、命令、事件、权限和重连；单独定义设备执行通道。

## 衡量与决策约定

- 不把工具调用减少、英文契约、并发或 token 下降直接等同于质量和速度提升。
- 默认复用已有构建、环境证据和通过记录，只运行与变化相关的验证。
- 流式、缓存、微压缩、辅助模型、持久内核、LSP、多 Agent 都要明确成本和适用条件，再决定是否启用。
- 每个大项讨论后，在对应章节记录确定范围、取舍、实施状态、验收记录和剩余问题。
